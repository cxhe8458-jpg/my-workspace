# company-product-scraper —— 公司产品数据抓取规范

> **本 skill 是唯一的抓取规范**（2026-09-29 由 `company-product-scraper` + `company-product-records` 合并而成）。
> HTML 标签/实体/表格结构的「这是什么 → 应还原成什么」查 **`html-param-extractor`**（配套词典，独立存放）。
> 抓完之后的字段映射、换 id、二次分类、复查见 `product-data-pipeline` / `product_category`（下游，不在本 skill 范围）。
> **同一份规范也维护在 `D:\SKILL.md`**（总纲 + 版本记录），两处内容必须一致。

---

## §0 目的与硬性红线

**唯一目的**：拿到每个产品的 ① **结构化参数**（记录式）② 对应 **PDF**（手册/规格书）③ **产品样图** ④ **渲染后的页面 DOM**。
合格标准只有一条：**参数准不准、PDF/样图全不全**。重要性排序：**PDF > JSON > 主图**。

**红线（任何情况不得违反）**：

1. **数据准确性高于一切**。宁可字段留空，**绝不臆造/猜测/硬编码/复制其他产品的值**；页面没有就留空。
2. **参数结构逐类目摸清**。同一家公司不同类目的参数承载方式常不同；**严禁"看一个类目就当通用结构套全站"**。没摸清不开抓。
3. **只存产品本身的样图**，过滤 banner/LOGO/模板图/侧栏缩略图/页脚图（**跨产品重复 = 模板，丢弃**）。
4. **输出格式固定**（§1/§4/§5），不增删字段、不改结构。
5. **不写"抓取报告/抓取说明"文件**（费 token 且无人看）：结论、遗留、例外**在对话里汇报**；需要留档的细节写进 `<公司>/scripts/` 的脚本注释。

## §1 输出路径与目录结构

**默认输出根目录**：`D:\公司数据自动化检验平台\公司数据\<公司全称>\`
——这是**审核平台**（`D:\数据审核归档平台`，内网 8010）的输入目录（可在平台配置里改）。抓完直接在平台里审核，
**归档走平台流程，不要手工往归档路径挪**。
（历史四隔离路径 `D:\公司产品数据提取_claude\...` 仅用于历史数据或用户明确指定时；修正数据严禁写回初版路径。）

```
<公司全称>\
├── scripts\                     ← 该公司全部脚本（必须，不与他公司混）
└── <产品大类>\[<二级分类>\]<产品最细分类>\
    ├── info.json                ← 必须
    ├── 主图.png                  ← 必须（.png、≥200×200）
    ├── <产品名>.html             ← 必须（详情页 HTML；JS 站存渲染后 DOM）
    ├── 参数图_N.png              ← 参数是图片时（.png、≥200×200；**不在 info.json 里登记**，见 §5.9）
    └── <原始文件名>.pdf          ← 有手册时
```

- 一级只放**产品大类**（+ `scripts\`）；目录名与官网类目/产品名**一致**（不翻译）；**中间分类层不得当最细产品**。
- 路径总长 ≤ ~150 字符。

## §2 命名铁律

1. **公司文件夹用完整中文法定名称**：从网站底部 Copyright / 关于我们 / ICP 备案里找；**禁止品牌简称、缩写、商标名**。
   （反例：`洛微科技` → 应为 `杭州洛微科技有限公司`；`明治传感` → `深圳市志奋领科技有限公司`。站内没有中文名时才用英文全称。）
2. **名称不得以 `.` 或空格结尾**（`Co., Ltd.` 结尾点是经典坑，Windows 会静默剥点导致文件夹打不开）；
   写目录/文件前一律 `re.sub(r'[\\/:*?"<>|]', '_', name).strip().rstrip('. ')`。
3. 文件名 = `info.json` 的 `产品名`（非法字符同规则替换）；**不要在文件名里保留 `%20` 等 URL 编码**（还原成空格）。
4. `<产品名>.html` 用产品名命名（与 `产品名` 字段一致）。

## §3 工作流（端到端，缺一步不交付）

### 3.1 判站型 → 定取页方式

```bash
python3 - <<'PY'
import requests
UA={'User-Agent':'Mozilla/5.0'}
t=requests.get("<URL>",headers=UA,timeout=20).text
print("len",len(t),"Body.js","Body.js" in t,"skeleton",len(t)<1500)
for k in ('__NUXT__','__NEXT','id="app"','id="root"','vue','react'):
    if k.lower() in t.lower(): print("SPA:",k)
PY
```

| 站型 | 特征 | 取页方式 |
|---|---|---|
| 静态 | 返回完整内容 | `requests` + BeautifulSoup |
| 万网/wezhan | ~900B 骨架 + `Body.js` + "站点已开启网站加速功能" | `python3 $SC/wanwang_decode.py <URL> -o page.html`（数据多已烘焙进 Body.js） |
| 完全动态 | 骨架里也没有数据，运行时 XHR 注入 | `python3 $SC/render.py <URL> -o page.html`（Playwright 渲染 + 列 XHR）；**用 `window.scrollTo` 触发懒加载** |
| 模板壳 + 后台接口 | 静态页写着"此处是详情内容…"之类占位、所有 id 返回同一份壳 | 渲染后**抓接口**（记下 `POST` 端点与参数，之后直接调接口，比逐页渲染快） |

- ⚠ 响应头不带 charset 时 requests 会按 ISO-8859-1 解码 → **中文全乱**：按 `<meta charset>` 自己 decode（或 `r.encoding='utf-8'`）。GBK/GB18030 站要显式解码。
- ⚠ 爬虫 UA 未必能拿到完整 HTML（有的站对爬虫只回骨架）；**渲染最可靠**。JS 站的 HTML 源码**必须存渲染后的 DOM**。

### 3.2 建清单（目录）

优先级：**sitemap → 类目/列表页（含翻页）→ 详情页"上一个/下一个"链 BFS → tab/AJAX 列表 → ID 扫描**。

- **sitemap 条数 ≠ 列表页条数时必须逐条查清**，三种情况区别对待：
  - **非产品页**（资质荣誉/产线/新闻/招聘）→ 按面包屑排除，不进产品目录；
  - **下架空壳页**（正文无产品内容，只剩 title/meta 残留）→ **不交付**，对话里简短汇报；
  - **列表页漏链的真实产品**（正文完整有参数）→ **必须补进目录**。
- **ID/pid 扫描**：URL 里是纯数字 id 的站，扫区间找隐藏产品；**先确认无效 id 的返回形态**——
  有的是 404、有的是"回落最小 id 产品"、有的是**同一份模板壳**（尺寸判据失效，得按内容判）。
- 翻页参数写死（`page`/`p`/`paged`/`pageid`/`PageIndex`…）时按站实测；**别把无参数的第一页当成全部**。
- 分类归属优先取**面包屑/页内「分类：」**；导航树与类目页冲突时以面包屑为准（爬虫写进 info.json 的 `所属大类` 也按此）。

### 3.3 逐类目摸清参数结构（红线 2，开抓前必做）

**每类目至少抽 1–2 个产品，用脚本把表格结构打印出来**，回答四个问题：

1. **参数在哪**：详情页？类目/列表页？PDF？图片？运行时 XHR？
2. **参数形态**：真表（带表头）/ 假表（绝对定位 div、`&nbsp;` 对齐）/ 图片 / 纯文本键值 / 混合？
3. **"一个产品"的粒度**：单品 / 一张表(多型号) / 一个料号？
4. **样图与 PDF**：有没有、在哪、怎么取。

**多型号表的红色警报**（命中任一 → 立刻按多型号处理，禁止用单型号逻辑）：同一列出现重复参数键 / 表中有空行分隔不同型号 / 单元格内容像产品名。

### 3.4 产品名与目录名（两个真实事故换来的）

- **H1 是营销语时不能当产品名**（如"轻松实现高速传输"）：改用目录名 / `<title>` 首段 / 面包屑；
  H1 超过 ~30 字一律判为标语。
- **不同子类目下同名产品会互相覆盖丢数据** → 目录名用**唯一标识**（目录名 slug 或 `产品名_id{pid}`），
  `产品名` 字段照实写官网名。
- ★**Windows 路径上限 260 字符**：长 H1（SEO 堆词，100+ 字）当目录名 + 长文件名会直接打不开 →
  这类产品**改用官网 URL slug 当目录名与 html 名**，`产品名` 字段仍存完整 H1。

### 3.5 样本先行

每种形态先抓 **2–3 个**，把 `info.json` 与页面**逐格核对**无误后再批量。批量时限流（产品间 `sleep`、下载间 `sleep`）、失败重试、共享 Session、真实 UA。

### 3.6 交付前自检（§8）→ 在审核平台里人工过一遍。

## §4 `info.json` 字段规范（UTF-8）

```json
{
  "产品名": "", "所属大类": "", "页面URL": "",
  "产品描述": "", "产品特点": "", "产品应用": "",
  "主图URL": "", "参数信息": {},
  "手册URL": "", "手册文件": ""
}
```

- **字段缺省用 `""`**（外层字段）；**`参数信息` 里的 5 个记录字段缺省用 `null`**（§5.2）；**任何地方都不用 `null` 之外的占位**。
- **三描述字段互不替代、缺一不可**（页面确实没有则留 `""`，不臆造）：

| 字段 | 装什么 | 页面取自 |
|---|---|---|
| `产品描述` | 一段**成文的概述**，讲这个产品是什么 | 产品概述/简介/系统描述 |
| `产品特点` | **要点式的特点/卖点**（多条用 `；` 连接，保持原文措辞） | 主要特点/优势/特性/亮点 |
| `产品应用` | **应用方向与领域** | 主要应用/应用领域/应用场景 |

- **描述全量入字段**：哪怕 1000+ 字也整段写入 `产品描述`，**不截断、不写"见 description.txt"、不落 txt 文件**。
- ⚠ `<meta name="description">` 是 SEO 套话且常张冠李戴，**不可当描述/应用用**。
- 历史字段名不要沿用：`上级名称`→`所属大类`；`产品特性/产品特征`→`产品描述`；**不再有独立 `主图` 字段**（主图固定存 `主图.png`）。
- `手册文件` 只在**磁盘真有该 PDF** 时才写。

## §5 参数解析（记录式，唯一标准）★核心

### 5.1 容器结构

```json
"参数信息": {
  "型号名或表名": [
    {"name": "光学参数-波长(Specifications-Wavelength)", "symbol": null,
     "value": "1064nm", "unit": "nm", "conditions": "532nm/355nm option"}
  ]
}
```

- **外层键 = 型号名**；**取不到型号名 → 用表名**（`技术参数`/`规格参数`/`①尺寸01 61*52*23mm`…；一页多表则每表一键，重名加 `(2)`）。
- **值 = 记录列表**，一条参数一条记录，**5 个字段固定**：`name / symbol / value / unit / conditions`，缺省 `null`。
- **没有 `group` 字段**：表头/分组字样**拼进 `name`**（§5.3）。
- 记录式下天然允许重名，**旧的 `(2)(3)` 重名后缀作废**；**序号列整列丢弃**（既不作 `name` 也不作值，
  判据：表头为「序号/序/NO」**或该列值全是纯数字**；行字段改用紧随其后的列，且**列名按原始列下标取**）。

### 5.2 五个字段怎么取

| 字段 | 取什么 | 细则 |
|---|---|---|
| `name` | **表头(父级)-字段名(英文)** 的组合 | 见 §5.3 命名规则；先去掉尾部脚注角标（`Thermal change dn/dT*` → `… dn/dT`） |
| `symbol` | 符号 | ① 表里有独立 symbol/符号列 → 直接用；② 写在 name 后的（`Thermal change dn/dT` 的 `dn/dT`）→ 拆出来；③ 无 → `null` |
| `value` | **值原文** | **单位保留在值里不删**（`4.41 g/cm³`）；值尾括号条件拆进 `conditions`；min/typ/max 见 §5.4；多值见 §5.5 |
| `unit` | 单位 | 优先级：**独立单位列 > name 括号里的纯单位 > value 里识别**；**单位只进 `unit`，绝不塞进 `conditions`** |
| `conditions` | **测试条件 / 适用条件 / 环境条件 / 备注**等一切限定信息 | 独立 conditions/备注列、name 或 value 后的**含数字括号**（`(20 – 100°C)`、`(1 μm)`）、行内条件列（`1064`/`532`/`355` 波长档） |

**拆分界线（以还原原文为核心，不强拆、不猜）**：

- **name 尾部括号**三分法：**含数字 → `conditions`**；**纯单位（`(nm)`/`(dB)`）→ `unit`**；
  **别名/说明性括号（`(Line Pair)`、`(bare)`）→ 留在 `name` 里不拆**。
- **符号**只在明确像物理符号时才从 name 拆（`dX/dY`、`λx`、`Δx`）；拆不出就留在 name。
- **单位识别**（值里）：取**首个数量**（含小数）后面紧跟的单位串 —— `>10W@500kHz` → `W`（不是 kHz）；
  `1-20Hz` → `Hz`；`< 13ps@1064nm` → `ps`；`～1.5mm` → `mm`；`<1%RMS` → `%`；`<20 μ rad` → `μrad`；
  判不出就 `null`（`M²<1.5`、`水冷`、`> 100:1` 无单位）。

### 5.3 ★命名规则：表头前缀 + 中英划分（不可违背）

1. **表头拼进 `name` 做父级**，半角 `-` 连接：`光学参数 + 波长` → **`光学参数-波长`**；无表头时直接用字段名。
2. **中英文都划分**，**但原文只有一种语言时不臆造另一种**：
   `波长 Wavelength` → **`波长(Wavelength)`**（**半角括号**；英文内部空格保留：`平均功率(Average power)`）。
3. **中文与中文拼、英文与英文拼**：
   `光学参数 Specifications` + `波长 Wavelength` → **`光学参数-波长(Specifications-Wavelength)`**。
4. **英文不在开头也照切**：`TTL 调制频率 Modulation Frequency` → `TTL 调制频率(Modulation Frequency)`。
5. **范围 = `name` / `value` / `unit` / `conditions` 都做**：
   `水冷 Water cooling` → `水冷(Water cooling)`；单语言的（`1064nm`、`Air cooling`、`M²<1.5`、`TEM₀₀`）**原样不动**。
6. 中英交错切不干净的（`15℃ (不结露) 15℃ (No condensation)`）→ **整串原样保留**，不硬切。
7. 英文段自带括号时允许嵌套：`脉冲持续时间(Pulse duration (FWHM))`。

### 5.4 ★最小值 / 典型值 / 最大值 → **一条记录**

```json
{"name": "光学参数-工作电压(Specifications-Operating Voltage)",
 "value": "min:90、typical:220、max:245", "unit": "V", "conditions": "@PO"}
```

- **标签统一英文** `min:` / `typical:` / `max:`（源表中文「最小值/典型值/最大值」也写英文标签）；**分隔符固定 `、`**。
- **空档保留档位**：只有典型值、其余格是 `–` 的行 → `min:–、typical:300mw、max:–`，**不省略档位**；
  官网原表**整格为空**的档位（真没填）→ 该档留空（`min:、typical:300、max:`）。
- **一个格 `colspan` 同时盖住三列** → 三档同值：`min:X、typical:X、max:X`。
- **不再拆成 3 条记录、也不再拆成 3 个键**。

### 5.5 一个格里多值 → **拆成多条记录**

```
"94.8 · 10^–6/K (1 μm)；67.7 · 10^–6/K (5 μm)；67.1 · 10^–6/K (10 μm)"
→ 3 条记录：同名同符号，value 各取一段，括号内容各进各自 conditions
```

仅当切出的 **≥2 段每段都自带限定**时才拆；否则整串保持一条（不无依据地切）。

### 5.6 ★合并单元格：先网格展开，再按"来源格"取值

**rowspan/colspan 一旦存在，就不能按 `<tr>/<td>` 顺序读**。做法：

1. 每个 `<td>` 按 `rowspan × colspan` **铺满它覆盖的格位**，并记录每格的**来源单元格**（`is_origin`）。
2. **跨列合并的格子**（一个值格横跨多个型号列/值列）→ 文本**复制**进它覆盖的每一个列键，而不是拼成 `"列名A-列名B"` 一个键
   （反面教材：`"最小值；Min-最大值；Max": "405、450…"` —— 列名直接消失、型号与参数当场错配）。
3. 判"是这一列自己的值"还是"公共参数复制来的"必须看**来源单元格**，**不许用"值是否相等"去猜**。
4. **绝不把同一行的多个原始格用 `；`/`/` 拼成一个值**（`"冷却方式": "风冷/水冷；水冷"` 等于把不同型号的值糊在一起）。
5. **单元格内部**的多行（`<p>` 换行、`<br>`）用 `；` 连接是允许的（同一格的多值）。

### 5.7 型号轴判定

- **先判表方向**：表头有型号/料号关键字列（`型号/料号/Part No/Model/PN`）→ 行式；**首列是一串参数名、型号在表头列上 → 转置表**。
  **判不出方向就停下来看页面，不许猜**。
- **型号名归一**：只收掉连字符两侧空白（`PWK-1064 - 10` → `PWK-1064-10`），不改写其他字符。
- **型号名可能跨多个物理列**（Word 排版把一格拆成几列）→ **逻辑上仍是一个型号，取该区间首列的值**。
- **空格处理分两种，先看表头行**：表头直接写了型号名（声明型）→ 空格=官网没填，存 `null`，**不许并入左邻**；
  表头只有通用词、型号名是跨全列模板串（未声明型）→ 模板串当**表名**（外层键），必要时用占比区间对齐多张表。
- 型号名**有空或重复 → 停下来核对**（多半是型号列选错/漏抓），不许用 `#2` 硬编。

### 5.8 组标题 / 分组列

- **通栏组标题行**（整行非空单元格**同源**，由一个跨全宽的合并格构成）与 **rowspan 分组列**都当**表头父级**，
  按 §5.3 拼进 `name`；**判据是同源，不是"值是否为空"**。
- 表里**完全没有分组** → 不加前缀，**不发明分组**。
- **组标题和列标签写在同一行**（`激光参数 | Signal | Idler`）→ 第一格是组、其余是列标签，**拆开读**。
- ⚠ **表尾通栏行是脚注不是组标题**（判据：后面还有没有普通参数行）；脚注（`说明Notes：…`）可作**一条记录**
  （`name` = 脚注标签、`value` = 内容），**不要塞进别的参数**。

### 5.9 参数是图片 / 不是参数

- **参数以图片呈现** → **只下载** `参数图_N.png`（`.png`、≥200×200），**绝不把图里的参数转录成键值**；
  `参数信息` 里**不登记** `参数图` 键（该产品只有图片 → `参数信息 = {}`）。
- ★**折线图、结构图、示意图、机械尺寸图不算参数图** —— 要么当样图，要么不抓；
  只有**真正的规格表/参数表截图**才算参数图。
- **判断"它是不是参数图"这一步不能省**：逐张目看，别把产品渲染图/原理图当参数图。

### 5.10 文本保真与角标（取文本一律走 `dom_text.py`）

- 取文本用 **`node_text()`**：`<sup>x</sup> → ^x`、`<sub>x</sub> → _x`（可转则 Unicode，见下）、
  `&nbsp;`/全角空格 → 空格、`<br>`/块级边界 → 单空格、**相邻文本节点零宽拼接**（插空格会拆散 `1×10^5` 这类科学计数法）。
  **禁止 `get_text(' ')`、禁止按 DOM 节点边界切 key/value**。
- 键值切分：先取**整段**文本，再按**第一个冒号**切（`split_kv`）；key 里绝不允许残留冒号。
- **角标口径（2026-09-28）**：能转 Unicode 就转，转不了**保留标记形式**，绝不去标记、绝不半截转换：
  `Iₜₕ` / `Rₛ` / `H₂O` / `1×10⁻⁸Pa` / `M²` / `cm³`；不可转的下标保留 `_x`（`V_F`、`λ_c`、`I_Fmax` → **整串不转**）、
  上标保留 `^x`（`10^F`、`10^–6`）。**源码已是 Unicode 的原样保留**。**页面没有任何角标标记时照原文，不许推断**。
  详细字符表见 **`html-param-extractor`**。
- 度符号破损写法归一：`368 ^°C` / `368 ^oC` → `368 °C`（本来就写对的 `100°C` 不动）。

### 5.11 参数为空 / 纯列头 / 序号列

- 页面确实没有参数 → **`{}`**（合法结果，落审核平台的"参数为空"提示；**不拿描述文字凑数**）。
- **纯列头**（`参数`/`Parameters`/`Unit`/`单位`/`Value`/`值`/`性能`/`规格`/`Specification`/`条款`）**不入库**（骨架而已）。
- 序号列丢弃（§5.1）；脚注处理见 §5.8。

## §6 图片、PDF、HTML

### 6.1 主图

- **只取产品本身样图一张**，存 `主图.png`（非 PNG 用 PIL 转，透明底合成白底）；**宽高均 ≥200×200**，
  小了先回站上换大图/原图 URL（列表页缩略图链接常可去尺寸后缀取原图），**禁止插值放大**；确实只有小图在对话里说明。
- **懒加载真实地址不一定是 `data-src`**：先打印 `<img>` 的**全部属性**再定采集属性（见过 `lazy=`、`data-original`、`data-src`、`_src`、
  `data-url`，占位统一是 `/npublic/img/s.png` 之类），否则频率统计只统计到占位图，会得出"全站没有产品图"的错误结论。
- **详情页没有产品图的兜底顺序**：① `og:image`/`twitter:image`（**要核验是否死链/张冠李戴**）
  ② **列表页产品卡片图**（按 `<a href=详情页URL>` 配对）；两者都拿到要交叉核验。
- **CDN 防盗链**：大量站点要求 **Referer**（不带 → 403/30 字节 0 图）——下载图片一律带 `Referer: <站点首页>`。
- 跨产品**重复出现的图 = 模板图**，必须剔除。

### 6.2 PDF

- 用**原始文件名**保存；`/filedownload/`、`down.asp?bid=` 这类要**跟随重定向**、按 `Content-Type` 定后缀；
  **404 记空不重试**；**磁盘实际存在**才算有 PDF（不看 `手册URL` 字段）。
- 同一份 PDF 挂多个产品的站，按型号栏核对归属；PDF 名字张冠李戴时**以内容为准**并汇报。

### 6.3 HTML 源码

- **每个产品必须存 `<产品名>.html`**（UTF-8，路径非法字符按目录名同规则替换），**JS 渲染站存渲染后的 DOM**。
  它是留档与复核依据：参数对不上时回查这份源码，不用重新请求站点。

## §7 反爬、限流与容错

- 常规：真实 UA、共享 `Session`、产品间 `sleep(0.3~1)`、失败重试 3 次、先小范围试探再放量。
- **被封/限流的征兆**（任一命中即处理，不要先花时间纠结）：403 / 429 / 502 / 503、连接超时或重置、
  正文变成网关页（`服务器繁忙`/WAF 挑战/恒定的极小响应体）、**原本正常的站突然全站失败**。
- **处理：立刻自建代理池换出口继续抓，不许原地干等、不许以此为由缩减交付**：
  1. 先确认是不是**只封动态页**（很多站**静态图片不封**，图片照旧直连下载）；
  2. 代理源：GitHub raw 的免费代理列表（proxifly / monosans / TheSpeedX / clarketm…），几十线程并发筛选；
  3. **验活必须打目标站真实内容页**（判据：HTTP 200 **且**正文含页面特征串 **且**不含封禁文案），**必须先解 gzip**
     （很多站一律返 gzip，按未解压长度判会把可用代理全判死）；
  4. 筛出的好代理**缓存复用**；取页按"直连优先 → 换代理 → 回退直连"；代理池会**掺假页**（企业网关登录页等），
     **入库前校验页面特征**，假页重抓；
  5. 已封过一次后，后续请求全程走代理，别再用直连去"试"（会延长封禁）。
- **WAF 类型站**：`_wtsjsk` 类 JS 挑战（抠出写 cookie）、安全狗、算术验证码、`visitToken`…——按站点记忆里的既有解法处理；
  没见过的先把挑战页存档再分析。
- **内容重复**：不少站把正文渲染两遍（PC/移动、或模板双份）→ **按内容哈希去重**，否则参数翻倍。

## §8 交付前自检（硬性，缺一项不交付）

```bash
python3 $SC/param_records.py --selftest   # 规则自测
```

1. **记录数 == 数据行数 × 型号数**（按**非空值格**逐一核对；多值拆分要按拆分后的条数对账）。
2. **值/名逐字回查**：每个 `value`/`name` 片段都能在页面单元格或正文里逐字命中
   （记录名要按 `组-字段(英文)` **折回页面写法**再查，否则全是假阴性）。
3. **角标护栏**：`param_records.check_records()` 无「下标/上标未转 Unicode」告警；
   `python3 $SC/dom_text.py --check <目录>` 的 red flag 要么为 0，要么逐条证明是误报（Min 列的合法负数）。
4. **字段完整**：`产品描述/产品特点/产品应用/参数信息` 四个字段都存在；无 `group` 残留；缺省值为 `null`（记录内）/`""`（外层）。
5. **min-typ-max 格式**：`^min:.*、typical:.*、max:.*$`。
6. **图片**：主图 1 张、参数图按需，全 `.png` 且 ≥200×200；跨产品重复图已清。
7. **HTML/PDF**：每个产品有 `<产品名>.html`；有 PDF 的目录里文件确实存在。
8. **命名**：遍历输出目录，凡 `n != n.rstrip(' .')` 或含 `\/:*?"<>|` 的名字都要修掉。

## §9 禁止事项（汇总）

❌ 臆造/猜测/复制别家产品的值 ❌ 用一个类目的结构套全站 ❌ 未摸清结构就写批量解析
❌ 主图用大类图/LOGO/模板图 ❌ 主图或参数图非 `.png` ❌ 图片 <200×200 靠放大凑 ❌ 缺 `<产品名>.html`
❌ 缺 `参数信息`（至少 `{}`）❌ 缺三个描述字段 ❌ 把中间分类当最细产品 ❌ 转录参数图里的文字
❌ 把同一行多个合并格拼成一个值 ❌ 用"值是否相等"判公共参数 ❌ 纯列头当参数 ❌ 脚注当组标题
❌ 序号当键名 ❌ 单位并进值或塞进 `conditions` ❌ 记录里出现 `group` 字段 ❌ 表头不拼进 `name`
❌ 中英不划分、或对单语言**臆造**另一种语言 ❌ 下标记成 `VF` / 可转角标留成 `^2`
❌ 抓取报告文件 ❌ 手工往归档路径挪数据

## §10 历史格式（仅用于理解存量数据）

2026-09 之前抓的数据用旧格式，**审核平台两种都兼容**；**新抓取一律记录式**，不要再产出旧格式：

| 旧格式 | 样子 | 现在怎么写 |
|---|---|---|
| 扁平键值 | `{"波长":"1064nm"}` | 一条记录：`{"name":"波长(Wavelength)","value":"1064nm","unit":"nm",...}` |
| 两层表 | `{行字段:{列字段:值}}` | 每行一条记录，列名进对应字段 |
| 型号字典 | `{型号:{参数:值}}` | `{型号:[记录…]}` |
| 参数图数组 | `{"参数图":["参数图_1.png"]}` | 只下载文件，json 里不登记 |
