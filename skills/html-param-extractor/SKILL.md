# Skill: html-param-extractor

# html-param-extractor —— HTML 参数标签识别与精准还原词典

**定位**：当 AI 在原始 HTML 中遇到标签/字符实体/表格结构时，查阅本 skill 以确定「这是什么 → 应还原为什么」。

**本目录同时持有两个数据文件**（2026-09-29 起归此）：`html_lables.json`（标签词典）、`table_lable.json`（表格词典）——
本 SKILL.md 是它们的**语义化版本**：把 JSON 里每条记录解释为可执行的还原规则。

**权威边界**：**上下角标口径以本 skill 的 T-01/T-02/T-03b 为准**（2026-09-28 用户指令：能转 Unicode 就转，转不了保留标记）；
抓取流程与参数落库格式见 `company-product-scraper`。

**与 company-product-scraper 的关系**：company-product-scraper 是**流程/工具**（脚本、目录、工作流），本 skill 是**词典/规则**（标签→含义→还原方式）。本 skill 不描述"用哪个脚本"，只描述"看到什么 HTML → 应该变成什么数据"。

# 第一篇：HTML 标签 → 参数语义词典

## 一、文本节点级标签（内联标签 —— 影响值内部语义）

每个标签按其**在页面中的视觉作用**定义还原规则。还原目标是生成**纯文本参数值**（非 HTML）。

### 【T-01】`<sup>` — 上标

**HTML 视觉含义**：基线上方的小号字。**参数中的真实含义**：指数、幂、标记序号。

**还原规则（2026-09-28 口径，与 `company-product-scraper` §5.10 一致）**：

1. **能转 Unicode 上标就转**；**整串字符都可转才转**（只要有一个字符没有 Unicode 上标形式 → 整串保留 `^` 标记）。
2. 源码里**已经是** Unicode 上标的**原样保留**（不要再降级成 `^2`）。
3. 与相邻文本节点**零宽拼接**，不插空格。

**可转上标字符**：`0-9` → `⁰¹²³⁴⁵⁶⁷⁸⁹`；`+ - = ( )` → `⁺⁻⁼⁽⁾`；小写拉丁字母 a–z →（`ᵃᵇᶜᵈᵉᶠᵍʰⁱʲᵏˡᵐⁿᵒᵖʳˢᵗᵘᵛʷˣʸᶻ`，`q` 无标准形式）。
**不可转**：全部大写字母、希腊字母、破折号 `–`／`—`、其它符号 → **保留 `^` 整串不转**。

|原始 HTML|还原为|说明|
|-|-|-|
|`1×10<sup>5</sup>`|`1×10⁵`|科学计数法指数|
|`m<sup>2</sup>`|`m²`|平方米|
|`cm<sup>3</sup>`|`cm³`|立方厘米|
|`10<sup>-8</sup>`|`10⁻⁸`|负指数（ASCII 连字符可转）|
|`λ<sup>-1</sup>`|`λ⁻¹`|波数|
|`10<sup>n</sup>`|`10ⁿ`|小写字母可转|
|`10<sup>F</sup>`|`10^F`|**大写无 Unicode 上标 → 整串保留 `^`**|
|`10<sup>–6</sup>`|`10^–6`|**破折号不可转 → 整串不转**|
|`R<sup>(1)</sup>`|`R⁽¹⁾`|标注序号（括号也可转）|

**致命错误示例**：`1×10<sup>-8</sup>Pa` 若被 `get_text(' ')` 处理 → `"1×10 -8 Pa"`（指数被拆散）。
**正解**：`node_text()` → `"1×10⁻⁸Pa"`（旧文写的 `1×10^-8Pa` 已是过期口径）。

### 【T-02】`<sub>` — 下标

**HTML 视觉含义**：基线下方的缩小号字。**参数中的真实含义**：化学式原子数、下标索引、变量编号、方向分量。

**还原规则（2026-09-28 口径）**：

1. **整串字符都可转 → 转成 Unicode 下标**。
2. **凑不齐就整串保留 `_` 标记** —— **绝不去掉标记、绝不做半截转换**（`I_Fₘₐx` 这种混排是错的）。
3. 源码里已经是 Unicode 下标的**原样保留**。

**可转下标字母**（仅这些）：`a e h i j k l m n o p r s t u` → `ₐ ₑ ₕ ᵢ ⱼ ₖ ₗ ₘ ₙ ₒ ₚ ᵣ ₛ ₜ ᵤ`；
数字 → `₀₁₂₃₄₅₆₇₈₉`；`+ - = ( )` → `₊₋₌₍₎`。
**不可转**：`b c d f g q v w x y z` **及全部大写字母**。

|原始 HTML|还原为|说明|
|-|-|-|
|`H<sub>2</sub>O`|`H₂O`|水分子|
|`Al<sub>2</sub>O<sub>3</sub>`|`Al₂O₃`|三氧化二铝|
|`SiO<sub>2</sub>`|`SiO₂`|二氧化硅|
|`n<sub>a</sub>`|`nₐ`|折射率 a 分量（a 可转）|
|`λ<sub>p</sub>`|`λₚ`|峰值波长|
|`I<sub>th</sub>`|`Iₜₕ`|阈值电流（t、h 都可转）|
|`R<sub>s</sub>`|`Rₛ`|小写 s 可转|
|`V<sub>F</sub>`|`V_F`|**大写 F 不可转 → 保留 `_`**|
|`λ<sub>c</sub>`|`λ_c`|**c 不可转 → 保留 `_`**|
|`I<sub>Fmax</sub>`|`I_Fmax`|**串内有 F → 整串不转**|
|`x<sub>max</sub>`|`x_max`|**x 不可转 → 整串不转**|

**致命错误示例**：

* `H<sub>2</sub>O` 被还原为 `H 2 O`（下标被当空格）→ 错。**正解**：`H₂O`。
* `H<sub>2</sub>O` 被展平成 `H2O`（去掉标记，丢失"低于基线"语义）→ 错。**正解**：`H₂O`（可转）／`V_F`（不可转，**保留 `_`**）。

### 【T-03】`<sup>` + `<sub>` 同时出现

**还原规则**：按下标（`_`/Unicode 下标）在前、上标（`^`/Unicode 上标）在后的顺序，按 DOM 子元素顺序依次处理。

* `X<sub>i</sub><sup>2</sup>` → `Xᵢ²`（可转）
* `I<sub>th</sub><sup>-1</sup>` → `Iₜₕ⁻¹`
* `<msubsup><mi>x</mi><mi>i</mi><mn>2</mn></msubsup>` → `xᵢ²`（MathML 同时上下标）

### 【T-03b】`<span style="vertical-align:sub|super">` — Word/富文本粘贴的角标

**识别**：`style` 属性里含 `vertical-align:sub`（下标）或 `vertical-align:super`（也写作 `sup`）。
Word 粘贴出来的表格**常常只有样式、没有 `<sub>/<sup>` 标签**——漏了这条会整站丢角标。
匹配前先把 style 里的空格去掉（`re.sub(r'\s+','',style)`）。

**还原**：与 `<sub>` / `<sup>` **完全一致**（走 T-01/T-02 的 Unicode 口径）。

|原始 HTML|还原为|
|-|-|
|`<span style="vertical-align:sub">th</span>`（前面是 `I`）|`Iₜₕ`|
|`<span style="vertical-align:super">2</span>`（前面是 `m`）|`m²`|

### 【T-04】`<br>` — 换行

**HTML 视觉含义**：强制换行。
**在参数中的真实含义**：逻辑分隔（多行参数的一个行边界）。
**还原规则**：转为**单个空格**（不插入换行符，因为参数提取后是纯文本键值，多行信息不跨行存储。如需保留多行语义 → 分多条记录）。

### 【T-05】`\&nbsp;` / 全角空格 `　`

**HTML 视觉含义**：不可断空格 / 全角空白。
**还原规则**：转为半角空格 ` `。连续空白折叠为**一个**空格。

### 【T-06】`<span>` / `<b>` / `<i>` / `<strong>` / `<em>` / `<u>` / `<small>` / `<big>`

**HTML 视觉含义**：样式/语义标记（粗体、斜体、下划线、字号变化）。
**在参数中的真实含义**：**无**——这些标签不影响参数值的内容语义，仅改变显示样式。
**还原规则**：标签丢弃，只取其**内部文本节点**。`<b>波长</b>` → `波长`。

### 【T-07】`<a>` — 超链接

**HTML 视觉含义**：可点击的链接。
**在参数中的真实含义**：分两种情况：

* 若链接文本是参数值本身（如 PDF 下载链接 `技术手册.pdf`）→ 取 `href` 作为 URL，文本作为文件名。
* 若链接文本是普通文本 → 取文本内容，丢弃链接。

### 【T-08】`<img>` — 图片

**HTML 视觉含义**：嵌入图片。
**在参数中的真实含义**：分三种：

* **参数图**：图片内容是规格表/参数列表 → 下载为 `参数图\_N.png`（2026-08-04 起统一 .png，宽高须 ≥200×200）
* **产品样图**：图片是产品实物照片 → 下载为 `主图.png`（同上，非 PNG 用 PIL 转，透明底合成白底）
* **模板图**：logo/banner/图标/装饰图 → **丢弃**

判据（同时满足 2 条以上视为模板）：尺寸极小 (<100×100px)、跨产品重复出现、位于页面非内容区（header/sidebar/footer/nav）、`src` 含 `logo/banner/icon/btn/template`。

### 【T-09】`<script>` / `<style>` / `<noscript>` / `<template>`

**还原规则**：**全部跳过**，不提取其内部任何文本。

## 二、块级边界标签

这些标签**不在值内部**出现，但定义了文本的逻辑边界。它们之间的文本节点是独立的参数或参数段落。

### 【B-01】`<p>` / `<div>` / `<section>` / `<article>` / `<li>` / `<dt>` / `<dd>`

**HTML 视觉含义**：块级容器。
**还原规则**：标签边界处插入**单个空格**作为分隔。

### 【B-02】`<h1>` / `<h2>` / `<h3>` / `<h4>` / `<h5>` / `<h6>`

**HTML 视觉含义**：标题。
**还原规则**：提取文本。若文本 >30 字 → 判为营销语，不作为产品名。若 ≤30 字 → 可作为产品名候补。

### 【B-03】`<tr>` — 表格行

**HTML 视觉含义**：表格中的一行。
**还原规则**：边界处插入空格分隔。但 `node\_text()` 完整处理时，同一 `<tr>` 内的所有 `<td>/<th>` 文本会自然拼接——因为相邻文本节点**零宽拼接**。

## 三、MathML 数学标记标签

当页面用 MathML（而非 `<sup>/<sub>`）表达数学公式时，每个 MathML 标签有其结构含义。

### 【M-01】`<math>` — 数学区域根元素

**还原规则**：递归提取其内部所有子标签内容。`<math>` 本身不产生输出。

### 【M-02】`<mi>` — 标识符（变量名、函数名）

**还原规则**：取其内部文本，原样输出。
`<mi>x</mi>` → `x`、`<mi>sin</mi>` → `sin`

### 【M-03】`<mn>` — 数字

**还原规则**：取其内部文本，原样输出。
`<mn>2</mn>` → `2`、`<mn>3.14</mn>` → `3.14`

### 【M-04】`<mo>` — 运算符

**还原规则**：取其内部文本，原样输出。
`<mo>+</mo>` → `+`、`<mo>×</mo>` → `×`

### 【M-05】`<msup>` — 上标构造

**结构**：`<msup><基><上标></msup>`
**还原规则**：基元素文本 + `^` + 上标元素文本。
`<msup><mi>x</mi><mn>2</mn></msup>` → `x^2`

### 【M-06】`<msub>` — 下标构造

**结构**：`<msub><基><下标></msub>`
**还原规则**：基元素文本 + `\_` + 下标元素文本。
`<msub><mi>x</mi><mn>1</mn></msub>` → `x\_1`
`<msub><mi>n</mi><mi>a</mi></msub>` → `n\_a`

### 【M-07】`<msubsup>` — 同时上标下标

**结构**：`<msubsup><基><下标><上标></msubsup>`
**还原规则**：基元素文本 + `\_` + 下标 + `^` + 上标。
`<msubsup><mi>x</mi><mi>i</mi><mn>2</mn></msubsup>` → `x\_i^2`

### 【M-08】`<mfrac>` — 分数

**结构**：`<mfrac><分子><分母></mfrac>`
**还原规则**：分子文本 + `/` + 分母文本。
`<mfrac><mn>1</mn><mn>2</mn></mfrac>` → `1/2`

### 【M-09】`<msqrt>` — 平方根

**还原规则**：`√` + 内容文本。
`<msqrt><mi>x</mi></msqrt>` → `√x`

### 【M-10】`<mroot>` — 任意次方根

**结构**：`<mroot><底><指数></mroot>`
**还原规则**：`∛底` 或底的文字描述（无标准纯文本表示时，保留数字语义）。

### 【M-11】`<mrow>` — 行容器

**还原规则**：递归取内部所有子标签内容并拼接。`<mrow>` 本身不产生输出。

## 四、HTML 实体 / 数字引用 / Unicode → 字符还原表

以下按**参数中出现频率从高到低**排列。当 HTML 中出现实体名（`\&xxx;`）、十进制数字引用（`\&#NNNN;`）或十六进制引用（`\&#xHHHH;`）时，还原为以下字符。

# 第三篇：HTML 表格 → 参数数据精准还原

## 五、表格标签结构语义——从 HTML 到矩阵

### 5.0 核心认知：表格 = 视觉矩阵 → 数据矩阵

HTML `<table>` 在浏览器中呈现为**二维矩形网格**。单元格通过 `colspan`（横向合并）和 `rowspan`（纵向合并）打破规则网格。还原的目标是**重建完整的矩形矩阵**——每个单元格位置明确，每个合并格子的值填到**所有被跨越的位置**。

### 5.1 表格结构的层级标签

每个标签定义表格中的一个**逻辑层次**。解析时必须逐层识别。

```
<table>                     ← 表格根容器。边界：从此处开始，到 </table> 结束。
├── <caption>               ← 表格标题。通常位于 <table> 最上方的文字描述。可选。
├── <colgroup>              ← 列组定义。包含 <col>，定义每列的属性。可选。
│   └── <col span="N">      ← 单列或多列的定义。span=N 表示该定义覆盖 N 列。
├── <thead>                 ← 表头区域。可选但强烈建议存在。
│   └── <tr>                ← 表头行。可有多行（多级表头）。
│       └── <th>            ← 表头单元格。scope="col"=列头，scope="row"=行头。
├── <tbody>                 ← 表格主体。数据行所在。
│   └── <tr>                ← 数据行。
│       └── <td>            ← 数据单元格。
└── <tfoot>                 ← 表脚区域。可含汇总行。可选。
    └── <tr>
        └── <td>
```

### 5.2 每个标签的准确含义与还原动作

#### 【TB-01】`<table>` — 表格根

**视觉含义**：一个完整的表格。
**参数等价物**：一个产品的参数组、或一个产品类目下多个型号的参数集。
**还原动作**：创建该表格的二维矩阵。从此处开始，`</table>` 处结束。

#### 【TB-02】`<caption>` — 表格标题

**视觉含义**：表格上方的标题文字。
**参数等价物**：该参数表的名称（如"光学参数"、"电学特性"）。
**还原动作**：提取其文本 → 作为表格的 `标题` 字段。若无 `<caption>`，尝试从表格前紧邻的 `<h2>/<h3>` 或上方文本推断。

#### 【TB-03】`<colgroup>` / `<col>` — 列组

**视觉含义**：定义列的宽度、样式、分组。
**参数等价物**：**无**。列样式不影响参数语义。
**还原动作**：可用于验证列数（`<col>` 数量 × span = 总列数），但数据提取时不依赖此标签。

#### 【TB-04】`<thead>` — 表头区域

**视觉含义**：表格的列标题行组合。
**参数等价物**：参数名的来源。表头中每个 `<th>`（或用作标题的 `<td>`）的文本 → 成为该列的**字段名（key）**。
**还原动作**：

1. 识别 `<thead>` → 其所有子 `<tr>` 均为表头行
2. 每个表头行中的单元格文本 → 作为列标题
3. 若有多行表头 → 组合为层级键名（如 `"电学参数-电流"`）
4. 若无 `<thead>` → 检查第一个 `<tr>` 是否满足表头条件（见 §5.4）

#### 【TB-05】`<tbody>` — 表格主体

**视觉含义**：表格的数据行区域。
**参数等价物**：每个 `<tr>` = 一行参数数据（可能是一个型号的全部参数，或多个型号中的一行）。
**还原动作**：逐行提取。每个 `<tr>` → 一个数据记录。

#### 【TB-06】`<tfoot>` — 表脚

**视觉含义**：表格底部的汇总行。
**参数等价物**：汇总信息或注脚说明。
**还原动作**：检查内容。若含参数数据 → 一并提取。若为纯说明文字 → 记录为备注。

#### 【TB-07】`<tr>` — 表格行

**视觉含义**：水平排列的一行单元格。
**参数等价物**：一条数据记录（一个型号或一个参数描述行）。
**还原动作**：提取该行所有 `<td>/<th>` 的文本，构成一个数组。

#### 【TB-08】`<th>` — 表头单元格（含 scope 属性）

**视觉含义**：加粗居中的表头文字。
**参数等价物**：该行/列的标题（字段名）。

**scope 属性决定表头的关联方向**：

|scope 值|含义|还原动作|
|-|-|-|
|`scope="col"`|该 `<th>` 是**其所在列**的标题|作为该列所有 `<td>` 的 key|
|`scope="row"`|该 `<th>` 是**其所在行**的标题|作为该行所有 `<td>` 的行标识|
|`scope="colgroup"`|该 `<th>` 是一组列的标题|作为其覆盖范围内所有列的父级 key|
|`scope="rowgroup"`|该 `<th>` 是一组行的标题|作为其覆盖范围内所有行的父级标识|
|无 scope|需推断位置|若在 `<thead>` 中 → `scope="col"`；若在 `<tbody>` 首列 → 可能为 `scope="row"`|

#### 【TB-09】`<td>` — 数据单元格（含 headers 属性）

**视觉含义**：普通表格数据。
**参数等价物**：一个具体的参数值。

**headers 属性**：值为一个或多个 `<th>` 的 `id`（空格分隔）。定义了该 `<td>` **直接关联的表头**。
**还原动作**：若 `headers` 属性存在 → 通过 `id` 查找对应 `<th>`，获取字段名，**忽略基于位置的推断**。

### 5.3 关键视觉属性的还原

#### 【CR-01】`colspan` — 横向合并

**视觉效果**：该单元格在视觉上横跨 `colspan` 列。
**未还原的后果**：该行后续单元格的列索引偏移，导致整行数据对不齐——**所有后续列的数据都会"漂移"到错误的表头下**。
**还原规则**：

* 创建矩阵时，该单元格的值**填充到其后 `colspan-1` 个连续列中**（每个被跨列的值都等于该单元格的值）
* 后续单元格的列位置 = 当前位置 + colspan

#### 【CR-02】`rowspan` — 纵向合并

**视觉效果**：该单元格在视觉上纵跨 `rowspan` 行。
**未还原的后果**：后续行该列位置为空，分析时该行数据丢失首列→**整行数据错位**。
**还原规则**：

* 该单元格的值**复制到后续 `rowspan-1` 行的同一列位置**
* 后续行处理时，该列位置标记为"已占用"→**遍历到该列时自动跳过**

## 六、colspan/rowspan 精确还原算法

以下是**唯一正确的还原算法**。任何其他实现导出错误结果 = 算法本质不同。

### 算法输入

* 一个 `<table>` 的 HTML 节点（已通过 §一 规则提取每个单元格的保真文本）

### 算法输出

* `g`：二维数组 `g\[row]\[col]`，每个元素是该位置的单元格文本
* 合并单元格的值已填充到所有被跨越的格子
* 矩阵为规整矩形（每行宽度相同）

### 算法伪代码

```
function grid(table):
    g = \[]                          # 二维结果矩阵
    occ = {}                        # 已占用坐标字典。key=(row,col)，value=单元格文字

    for each <tr> in table (行索引 ri):
        确保 g 有 ri 行（补齐）
        ci = 0                      # 当前列指针

        for each <td> or <th> in 当前<tr>:
            # ① 跳过被 rowspan 占用的列
            while occ 中有 (ri, ci):
                ci += 1

            # ② 读取合并属性
            rs = int(cell.rowspan or 1)
            cs = int(cell.colspan or 1)

            # ③ 获取单元格文本（⚠ 必须使用 node\_text()，见 §一）
            val = node\_text(cell)

            # ④ 填入当前位置
            确保 g\[ri] 有 ci 列
            g\[ri]\[ci] = val

            # ⑤ 标记所有被跨格子的值
            for dr in 0..rs-1:
                for dc in 0..cs-1:
                    if dr != 0 or dc != 0:           # 排除自身（已在步骤④填入）
                        occ\[(ri+dr, ci+dc)] = val    # 标记，后续行/列处理时可见

            # ⑥ 列指针前进
            ci += cs

    # ⑦ 补填：将 occ 中尚未在 g 中显式出现的格子填入（首列 rowspan 沿展）
    for each (r, c), val in occ:
        确保 g 有 r 行
        确保 g\[r] 有 c 列
        if g\[r]\[c] 为空:
            g\[r]\[c] = val

    return g
```

### 算法实例：rowspan=3 的首列合并

```
HTML:                               还原后的矩阵 g:
<tr><td rowspan=3>器件A</td>          g\[0] = \["器件A", "100W", "808nm"]
     <td>100W</td>                    g\[1] = \["器件A", "200W", "1064nm"]
     <td>808nm</td></tr>              g\[2] = \["器件A", "300W", "1310nm"]
<tr><td>200W</td>
    <td>1064nm</td></tr>
<tr><td>300W</td>
    <td>1310nm</td></tr>
```

**若未填充 rowspan**：`g\[1]\[0] = ""`、`g\[2]\[0] = ""` → 提取时"200W"跑到第一列、"1064nm"跑到第二列 → **全表数据错位**。

### 算法实例：colspan=2 的标题行

```
HTML:
<tr><td colspan=2>光学参数</td></tr>
<tr><td>功率</td><td>波长</td></tr>
<tr><td>100W</td><td>808nm</td></tr>

还原后的矩阵:
g\[0] = \["光学参数", "光学参数"]   ← 标题行，两个格子都是"光学参数"
g\[1] = \["功率", "波长"]            ← 表头行
g\[2] = \["100W", "808nm"]          ← 数据行

检测：g\[0] 两列内容相同且原始 colspan=2 → 识别为标题行 → 跳过（不作为数据）
```

## 七、表格结构语义识别

矩阵建立后，需要对矩阵各行**分类**——哪些是标题、哪些是表头、哪些是数据。分类错误 = 导出结构错误。

### 7.1 行分类规则

|行类型|判定规则|参数含义|
|-|-|-|
|**标题行**|该行只有 1 个 `<td>`/`<th>`，且原始 colspan ≥ 总列数的一半|表格/分组的名称文字|
|**表头行**|在 `<thead>` 中 → 100% 是表头；或矩阵前几行中所有单元格内容都为短文本（<15字）且不含数字和单位|列为参数名|
|**数据行**|非标题、非表头的所有行|一个产品/型号的参数值|
|**空行**|所有单元格 trim 后为空|视觉分隔，丢弃|

### 7.2 多级表头处理

若表头占 2+ 行（如第 1 行是"大类"，第 2 行是"具体参数"），需组合：

```
表头行 1: \["光学参数", "",           "电学参数", ""]
表头行 2: \["中心波长", "光谱宽度",  "工作电流", "阈值电流"]

组合为:  \["光学参数-中心波长", "光学参数-光谱宽度", "电学参数-工作电流", "电学参数-阈值电流"]
```

### 7.3 标题行的 colspan 覆盖判定

标题行可能不覆盖整表而只覆盖部分列：

```
g\[0] = \["A组", "A组", "B组", "B组"]   ← 两个 colspan=2 的 td
g\[1] = \["功率", "波长", "电压", "电流"]
```

此时：`"A组"` 覆盖前两列、`"B组"` 覆盖后两列。组合表头为 `"A组-功率"` 等。若按整组输出 → 可拆为两个子表。

## 八、多型号识别与精确拆分

### 8.1 型号键列检测

在表头中搜索包含以下任意关键词的列（不区分大小写）：

```
型号  料号  Part Number  PartNumber  Part No  Model  PN  规格型号
```

第一个匹配到的列 = **型号键列**。

### 8.2 多型号 vs 单型号判定

|条件|判定|输出格式|
|-|-|-|
|数据行 = 1 行|**单型号**|扁平字典 `{key: value, ...}`|
|数据行 > 1 行 且 找到型号键列|**多型号**|型号字典 `{型号值: {key: value, ...}, ...}`|
|数据行 > 1 行 且 **未**找到型号键列|**多型号（型号列不明）**|序号键 `{"型号1": {...}, "型号2": {...}}`，标注 `"需复核"`|

### 8.3 型号去重

若同一型号值在多行中出现（如连续行表示同一型号的多个 variant）：

* 第 1 次 → `"DFB-1310": {...}`
* 第 2 次 → `"DFB-1310#2": {...}`
* 第 N 次 → `"DFB-1310#N": {...}`

## 九、多表识别与去噪

一个页面可能包含多张表。需要识别哪些是参数表、哪些不是。

### 9.1 参数表的正面特征（≥3 条命中 = 参数表）

|#|特征|
|-|-|
|1|表头含参数关键词：`波长/功率/电压/电流/温度/尺寸/精度/范围/频率/阻抗/效率`|
|2|表头含单位：`nm/mm/μm/W/V/A/Hz/dB/℃`|
|3|标题含参数关键词：`参数/规格/技术/性能/指标/特性`|
|4|数据单元格含数值+单位模式（如 `100W`、`808nm`）|
|5|在 `<thead>` 中或使用 `<th>`|
|6|位于页面中"参数/规格"区域（通过周围标题或 class 判定）|
|7|表头含型号键列关键词|

### 9.2 非参数表的负面特征（≥1 条命中 = 跳过）

|#|特征|
|-|-|
|1|表头/单元格含：`状态/数量/询问/添加到/购物车/加入/价格/￥/$`|
|2|单元格含大量 `<a>` 链接（导航/目录表）|
|3|单元格含 `<input>` / `<select>` / `<button>` / `<form>`（表单）|
|4|所有行只有 1-2 个单元格且无表头（列表型，非表格）|
|5|表放置于 `<nav>` / `<footer>` / `<aside>` / `<header>` 中|
|6|单元格主要为 `<img>` 且无 alt 文本（纯图片表，非参数文本）|

## 十、1 列续行表（特殊形态）

### 识别特征

* 表只有 2 列：第 1 列是 key，第 2 列是 value
* 某行只有 1 个 `<td>`（或 colspan=2）→ 该行是**上一行 value 的续写**

### 还原规则

```
行1: <td>波长</td>    <td>808nm, 1064nm,</td>
行2: <td colspan=2>1310nm, 1550nm</td>          ← 1列，是行1 value 的续写
还原: "波长": "808nm, 1064nm, 1310nm, 1550nm"
```

用 `；` 连接续写内容到上一行的 value。

## 十一、文本保真还原的总规则

以下规则跨越所有标签和结构，是**终极的硬性约束**：

### 规则 1：相邻文本节点零宽拼接

```
<span>1×10</span><sup>-8</sup><span>Pa</span>
```

→ 文本节点 `"1×10"` + sup 处理 `"⁻⁸"` + 文本节点 `"Pa"` → **无缝拼接** → `"1×10⁻⁸Pa"`
→ ❌ 若它们之间插入了空格 → `"1×10 ⁻⁸ Pa"` → 错

### 规则 2：先整段提取、后切分键值

```
错误做法：逐 DOM 节点取文本 → 按节点边界定为 key/value
<td>
  <span class="label">波长</span>
  <span class="value">808<sup>±5</sup>nm</span>
</td>
```

→ ❌ 第一节点→key="波长"，第二节点→value 时 sup 被断 → `value="808 ±5 nm"`
→ ✅ 先 `node\_text(td)` → `"波长 808^±5nm"`，再按冒号切（此处无冒号，则整段为单值）

### 规则 3：连续空白折叠

`\&nbsp;\&nbsp;\&nbsp;` → 一个空格
`　　`（全角） → 一个空格
`\\t \\r \\n` → 一个空格

### 规则 4：skip 标签的内容绝不提取

`<script>`、`<style>`、`<noscript>`、`<template>`、`<svg>` 的**全部子内容**跳过。

## 十二、还原后的键值断裂自检

还原后的每个 key-value 对需通过以下检查。**任何一条命中 = 还原过程出错，必须回溯修正**：

|#|检查项|条件|示例（bad）|
|-|-|-|-|
|1|key 末端截断|key 以 `×10` / `x10` / `X10` 结尾|`"测量范围：1×10"` → 值 `"5 \~1×10^-8Pa"`|
|2|key 含冒号|key 中有 `:` 或 `：`|`"输入电压：AC"` → 值是 `"DC"`（多冒号切错）|
|3|数值被拆到两边|key 以数字结尾 + value 以数字/`-` 开头|key=`"波长808"` value=`"±5nm"`|
|4|上标丢失底数|value 以 `^` 或 Unicode 上标开头|value=`"⁻⁸Pa"`／`"^-8Pa"`（前面数字去哪了）|
|5|负号拆断|value 以 `-数字` 开头但不是完整负数或区间|value=`"-8 Pa"`|
|6|游离数字单位|value 中 `数字 单位` 孤悬（中间无连接符）|value=`"100 W 808 nm"` → 应为 `"100W 808nm"`|
|7|**下标未转 Unicode**|出现 `_` + 全可转小写串（`(?<![0-9A-Za-z])[0-9A-Za-z)]_([a-z]{1,4})` 且该串全在可转表内）|`I_th` → 应为 `Iₜₕ`；`R_s` → 应为 `Rₛ`|
|8|**上标未转 Unicode**|出现 `^` + 全可转串（`[0-9A-Za-z)]\^([0-9+\-=()a-z]{1,3})`）|`cm^2` → 应为 `cm²`；`10^-8` → 应为 `10⁻⁸`|

> **误报判读**：`V_F`、`λ_c`、`R_S`、`I_Fmax`、`x_max`（不可转下标保留 `_`）与 `10^F`、`10^–6`（不可转上标保留 `^`）
> 是**合法写法**，不算 flag；只有"**全可转却还留着标记**"才是问题。
