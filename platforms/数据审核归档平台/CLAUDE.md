# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 这是什么

**数据审核归档平台**，只做两件事：**审核**产品数据 → **归档**审核完的公司。
原为单机自用，现已**部署到公司内网**（`0.0.0.0:8010` + 单账号登录，见 `内网部署说明.md`）——
注意它的并发假设仍是单人：公司阶段聚合、内存索引、整份记录读改写都没有为多人同时写做保护，
**一家公司同时只应有一个人处理**。
它是上一代「公司数据自动化检验平台」的重写版，刻意只保留这两个模块；统计分析、
Skills 规则库、重抓 prompt 闭环、AI 截图识参数等全部不再提供。

界面文案、数据字段、JSON 键一律中文，编辑时保持这个约定。

## 运行

```bash
python3 run.py               # http://127.0.0.1:8010
python3 tools/selftest.py    # 端到端自检（临时目录造假数据，不碰真实数据）
python3 tools/migrate.py     # 从上一代平台迁移记录（先出对账报告，加 --apply 才写入）
```

依赖：`fastapi` `uvicorn` `requests` `pillow`，`httpx`（仅 selftest 的 TestClient 用）。
无构建步骤、无测试框架，`selftest.py` 就是全部的测试——它按流程分段跑
（扫描/标记/归档门槛/数据修正/一键通过/归档撤回/删除撤销/路径安全/写盘容错/坏文件隔离），
**没有单测粒度，改了任何一段业务都跑整个脚本**，末尾打印通过/失败计数并以退出码反映。

**改了后端必须重启进程**（路由在进程启动时加载）：内网部署下是
`bash deploy/start.sh`（内部调 `systemctl --user restart audit-archive`，并等就绪自检），
Windows 侧对应 `deploy\restart_deploy.bat`。**不要**再直接 `python3 run.py`——
会和 systemd 抢 8010 端口。想让界面提醒"该重启了"，就把
`APP_VERSION`（app/main.py）和 `FRONT_VERSION`（static/js/api.js）**同时 +1**：
浏览器拿到新前端、后端仍是旧进程时两者不等，顶部挂红色横幅并写清是哪一边旧了，
重启后横幅每 3 秒自查、自己消失。前端资源已全局禁缓存，改完普通刷新即可。

**改了功能/交互要同步改 `使用说明.md`**——那是给使用者写的唯一说明书，与代码脱节即失效。

## 三处数据，边界不能混

| 位置 | 内容 | 谁写 |
|---|---|---|
| `公司数据/`（默认在上一代平台目录下，可配置） | 被审核的产品数据：`公司/分类…/产品/info.json` + 图片 + PDF + HTML | 爬虫写；本平台**就地修正**（图片/PDF/URL） |
| `~/.local/share/审核归档平台/` | 全部审核状态：`records/{公司}.json`、`归档台账.json`、`已删除产品.json`、`backups/`、`config.json`、`errors.log`；外加纯缓存 `索引缓存.json`（可随意删） | 只有本平台写 |
| 归档路径（默认 `/mnt/d/已审核数据`） | 审核完毕后整体搬过去的公司文件夹 | 本平台写；**下游流程也会动这里**（改名、搬走），台账会因此漂移，属正常 |

**状态必须留在 WSL 原生盘。** 上一代把状态放 `/mnt/d`（9p 挂载 NTFS），
`os.replace()` 间歇失败导致审核标记静默消失（实测丢过数据）。原生 ext4 上
rename 才是真原子。产品数据在 `/mnt/d` 是既定事实，只读它、按需改它。

新增任何状态文件都要在 `infra/paths.py` 里建常量，**并同步加进 `tools/selftest.py`
顶部的 paths 覆盖块**——那段代码在 import store/scanner 之前把每个路径逐个改到 tmp，
漏一个，自检就会往真实状态目录写。

## 架构

```
app/
  main.py                 装配：全局异常处理、禁缓存中间件、路由注册。不写业务
  api/                    HTTP 层：参数校验 + 调用 service，业务异常翻 400
    inspect.py            公司/产品/标记/一键通过/数据修正/产品增删
    archive_api.py        归档候选、归档、撤回、台账、配置
    files.py              /files 产品文件、/api/proxy 原网页代理
  services/               业务规则的唯一所在地
    review.py             三态判定、公司聚合、一键通过
    archive_svc.py        归档门槛、移动、撤回、台账校验
    fixes.py              图片/PDF/URL/误提取产品，含失败回滚
  infra/
    paths.py              全平台唯一路径出口
    store.py              原子写、审核记录、台账、备份
    scanner.py            内存索引、后台扫描、HTML 检测、路径安全
    auth.py               内网鉴权：单账号、PBKDF2 口令、HMAC 签名会话 cookie
                          （中间件在 main.py，除 auth.OPEN_PATHS 外全站拦截；
                           新增不需登录的路由必须同时加进 OPEN_PATHS）
static/js/                api / ui / compare / inspect / fixes / archive / main
deploy/                   内网部署脚本（Windows 双击 bat + WSL start.sh）
                          结构对齐 /mnt/d/自动化数据处理/数据处理平台/deploy
```

**`deploy/*.bat` 必须 CRLF + 纯 ASCII**（界面文案用中文那条规矩在这里不适用）。
cmd 按 936 代码页读脚本并按字节偏移取下一条命令，文件里有 UTF-8 中文或 LF 换行就会
解析错位：`rem` 前缀被吃掉、注释被当命令跑，**`exit /b` 也会失效**导致脚本继续执行。
要中文输出就 `chcp 65001`，要中文路径就把那段挪进 `.sh`（见 `deploy/show_access.sh`）。
细节与验证方法见 `内网部署说明.md` 第七节。

前端**没有模块系统**：7 个脚本按 `index.html` 里的顺序裸加载、共享同一批全局
（`S` 全局状态、`api()`、`$`/`$$`/`esc`、`toast`/`showModal`/`confirmModal`/`busy`/`pushUndo`）。
加文件要自己加进 `index.html` 的 `<script>` 列表，**顺序即依赖顺序**（`api.js` 必须最先，
`main.js` 必须最后——它在文件末尾直接执行启动逻辑）。HTML 内联 `onclick` 调用的函数
必须挂 `window.`。全局状态刻意只有 `S` 一份，别再引入第二份。

## 领域模型

**只有三态**：`未检 → 通过 | 有问题`。`有问题`必须带一行说明（后端强制）。
公司阶段（`未审核 / 审核中 / 可归档 / 已归档`）由产品状态**聚合得出，不单独存储**——
两处状态会互相打架。

- **产品 = 含 `info.json` 的目录**，`os.walk` 到哪层算哪层，目录层级即分类。
  记录键是公司名开头的相对路径（`公司/分类/产品`），全平台统一用它寻址。
- **`info.json` 字段契约**（爬虫写的中文键）：`页面URL` `手册URL` `主图URL` `主图`
  `手册文件` `参数信息` `产品描述` `产品应用` `产品特性`/`产品特征`/`产品特点`
  `上级名称`/`所属大类`/`二级分类`/`所属细分类` 等。
  **不要再往代码里加"认得的键"清单**：除 `scanner.INFO_SURFACED`（已在别处展示的
  5 个键）外，其余一律由 `scanner.extra_info()` 兜底进「产品信息」面板，
  爬虫加新字段不用改平台代码。`INFO_ORDER` 只管排序，漏列不会导致字段消失。
  这段是补上来的：实测 288 家公司里 `产品描述`/`产品应用` 各占 85%、`产品特点` 占 27.5%，
  过去一个都没展示过——**采了却没人看得见**。
  `extra_info()` 现读 info.json 而不进内存索引：单文件读约 11ms、只在点开产品时发生一次，
  塞进索引则会让 47MB 的快照再涨一截，且快照结构一变老快照全失效、重启要冷扫几分钟。
- `参数信息` 有四种形态（`scanner.classify_params`）：扁平键值 / 多型号嵌套 / 纯参数图 / 空。
  **`参数图` 键是图片引用不是参数项，判形态前必须先剥掉**，否则有参数表的产品会被当成纯图片。
  **整个 `参数信息` 也可能就是个图片文件名数组**（凯普林等站点，实测 12 个产品）——
  必须判成 `images`，落到 `flat` 的话前端 `Object.entries()` 会把数组下标当参数名，
  渲染出「0 | 参数图_1.jpg」这样一张根本不存在的参数表。
- **图片分类完全由文件名前缀决定**：`主图*` = 主图，`参数*` = 参数图，其余归主图。
  这是 `scanner` 与 `fixes` 之间的隐式契约，所以"改归类"实现为**重命名**。
  每次动完文件都由 `fixes._sync_images()` **按磁盘现状重算** `info.json` 的引用
  （而不是增量改字段），引用因此永远不会指向已删文件。
- **HTML 检测是自动的**：扫描时看目录里有没有 `.html`，只展示徽标与「缺HTML」筛选，
  **不阻断标记与归档**（这是与使用者确认过的）。
- **一键通过只动「未检」**，已标「有问题」的保持不动，二次确认里写明将影响几个。
- **归档门槛：全部产品必须是「通过」**。不达标时返回卡住的产品清单，前端可一键直达。
- **归档 = 移动整个公司文件夹**。已归档公司仍可只读复查（`company_root()` 回落到台账
  目标路径），一切写操作被 `review.assert_writable()` 拦下；`撤回归档`是修改已归档数据
  的唯一正规入口。台账里目标目录已不在的历史条目**不进审核列表**（否则一堆空卡片），
  但仍留在台账里可查。

## 这些坑是上一代用真实事故换来的，不要改回去

1. **状态写盘**：`store.atomic_write_text()` 重试 + 原地覆写兜底 + 绝不留 `.tmp`。
   写入静默失败等于丢标记。
2. **读坏文件要隔离**：`read_json` 遇到解析失败会把坏文件改名留证。直接返回空默认值的话，
   下一次保存会把"空"当全量写回去，整个公司的记录清零。
3. **先备份 → 动文件 → 写 info.json，失败全部回滚**（`fixes.py`）。上一代顺序反了，
   于是出现"文件已改、接口报失败"，用户照提示重试就造出重复数据。
   同理 `archive_svc.archive()` 必须**移动成功后才写台账**。
4. **报错必须说人话**：全局异常处理器返回真实异常文本并把回溯写进 `errors.log`。
   注意 `traceback.format_exc()` 在处理器里只会写出 `NoneType: None`，必须
   `format_exception(type(exc), exc, exc.__traceback__)`。
5. **前端资源禁缓存**：`?v=` 那套破缓存的版本号本身写在会被缓存的 index.html 里，
   会自锁死（后端已更新、界面永远跑旧 JS、提示重启的横幅永不消失）。
6. **写操作报错后自动回查磁盘真实状态**（`fixes.js` 的 `fixFailed`），并明确劝阻重试。
7. **拖图改归类**：落点绑在整个 `.panel` 而非 `.img-grid`（标题栏和内边距原本是死区）；
   拖动期间 `#mark-dock` 等常驻浮层必须 `pointer-events:none`，否则 drop 落在标记按钮上
   静默失败；同时提供「→参数图/→主图」按钮作为不依赖拖拽的路径。
8. **对比窗口**：官网发 COOP 时弹窗被切断，`cmpWin.closed` 恒为 `true`——它表示
   "还能不能操作"，**不是"窗口还在不在"**。窗口开没开用 `cmpWinOpen` 自己记账，
   并用 `cmpShownPath` 在浮动条上明示窗口停在哪个产品。
   切断的后果不止"提示一下"：窗口关不掉、换不了页，**连 `window.open` 同名复用都失效**
   （窗口名只在同一浏览上下文组内可见），于是每审一个产品攒一个孤儿窗口。
   解法是别让顶层文档是官网——COOP 只管顶层，所以这类站点改开**同源跳板窗口**
   `static/cmpwin.html`（官网放它的 iframe 里；官网禁止内嵌就退回 `/api/proxy` 代理渲染）。
   跳板窗口永远同源可控：切产品由 opener 直接调它的 `__cmpShow()` 换页，关对比时能真关掉。
   哪些站点走跳板：后端 `/api/pagecheck` 读响应头（COOP / X-Frame-Options / frame-ancestors，
   按域名缓存 10 分钟）；探测不到就照旧开真窗口，开完 1.5 秒回头看是否已被切断，
   是就把域名记进 `cmpSevered`（localStorage），下次自动走跳板。**别再退回"只提示不换路"**。
9. **点平台不要抢焦点**：`cmpWin.focus()` 会夺走操作系统焦点，导致拖拽被中止、
   `Ctrl+V` 粘到官网、快捷键失灵。只在点空白/纯阅读区域时才抬升。
10. **路径安全**用路径级判断（`root in full.parents`），不能用 `str.startswith`——
    公司「A」下的 `../AB/x` 会被前缀匹配放行。
11. **粘贴图片时 `getAsFile()` 必须在事件同步阶段调用**（`ui.js`），`await` 之后
    `clipboardData.items` 已失效，粘贴会静默变成空。

## 性能约束

`/mnt/d` 每次系统调用约 11ms，是 WSL 原生盘的 110 倍。**绝不在请求路径里遍历目录**：
一律读 `scanner` 的内存索引，索引只在启动预扫、显式刷新、单产品改动后
`rescan_product()` 就地重扫时更新。改了产品文件就必须调 `rescan_product()`，
否则界面读到的还是旧索引。

**单个 `.is_dir()` 也是 11ms，成百上千次就是秒级。** `is_archived/company_root/
list_companies` 全部走 `scanner._dir_state()` 的 5 秒缓存——曾经每家公司 stat 两遍，
`/api/companies` 要 1.8~2.3s，而前端首扫期间每 2.5 秒轮询它一次，请求首尾相接又和
后台扫描抢同一个挂载，界面直接卡死。自己搬动了目录（归档/撤回）要调 `invalidate_dirs()`，
`remove_company()` 里已经带上了。

**索引快照** `索引缓存.json`：冷扫一家 215 产品的公司要 4.7s，108 家就是几分钟。
进程被 OOM 杀掉重启后没有它，界面会有好几分钟全是「后台扫描中」。快照只存产品结构、
**不含任何审核状态**，启动时回填、全量刷新后重写；加载时按 `known_companies()` 过滤，
否则台账里早搬走的公司会变成打不开的空卡片。

## 键盘层

`static/js/main.js` 的 `KEYMAP` 是快捷键**与**帮助弹窗的唯一来源，加快捷键就加在那张表里。
全局 keydown 在修饰键、输入框、弹窗打开、非审核页、只读模式下一律不拦截。
