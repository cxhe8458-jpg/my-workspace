# 内网部署说明

面向管理者（部署、改口令、排障）。给审核员看的是 `使用说明.md`。

部署方式与隔壁 `D:\自动化数据处理\数据处理平台\deploy` 一致：**Windows 侧双击 bat**。
差别只有三处，见第七节。

---

## 一、先读这三条风险

这个平台原本是**单机自用**工具，改成内网多人用之后有三件事没被解决，
用之前请确认你能接受：

1. **全公司共用一个账号，审核历史分不清是谁改的**。历史里只会记「标记通过」，
   记不下是谁标的。能查到的只有访问来源 IP（`deploy\view_access.bat`）。
2. **两个人同时开同一家公司会互相踩**。一方点「归档」会把整个公司文件夹移走，
   另一方正在改的图片/PDF 操作就会失败。约定好一家公司同时只有一个人处理。
3. **HTTP 明文 + 弱口令**。`123456` 只挡随手打开的人。能连到这个端口的人
   就能归档、删产品、移动 D 盘上的真实数据。**强烈建议改掉默认口令**（第五节）。

另外：对比模式的「代理」功能会让服务器代抓任意 URL（`/api/proxy`），
登录后的人可以借它探测内网其它服务。仅限可信员工使用。

---

## 二、部署三步（Windows 侧，右键"以管理员身份运行"）

```
deploy\deploy_setup.bat        ← 跑一次：端口转发 + 防火墙 + 开启防火墙日志
deploy\install_autostart.bat   ← 跑一次：登录 Windows 时自动起服务、自动刷新转发
deploy\deploy_check.bat        ← 随时自查：服务活着吗、口令对吗、转发指对了吗
```

装完同事打开：**http://192.168.2.106:8010**，用 `admin` 登录。
（地址是 DHCP 发的、会变：拿不准时跑 `deploy\deploy_check.bat`，第 [4] 项打印的就是当前地址）

日常还会用到（**不需要管理员**）：

| 文件 | 干什么 | 什么时候用 |
|---|---|---|
| `deploy\restart_deploy.bat` | 重启服务 | **改了后端代码之后**（路由在进程启动时加载） |
| `deploy\deploy_check.bat` | 体检 | 同事说打不开时第一个跑它 |
| `deploy\view_access.bat` | 看谁访问过（需管理员） | 想知道有哪些人在用 |

WSL 里等价的命令：

```bash
bash deploy/start.sh                       # 重启 + 等就绪 + 自检
systemctl --user status  audit-archive     # 看状态
journalctl --user -u audit-archive -n 50   # 看日志
```

## 三、当前状态

| 项 | 值 |
|---|---|
| 监听 | `0.0.0.0:8010`（配置项 `host`/`port`，在 `~/.local/share/审核归档平台/config.json`） |

## 四、"服务器一切正常，同事就是连不上"

九成是这个原因，值得单独记一笔。

WSL2 的网络是 NAT 的，同事的请求要经过一次转发：

```
同事  →  Windows 192.168.2.106:8010  →（portproxy）→  WSL 172.28.110.16:8010  →  平台
```

`172.28.x.x` 是每次启动 WSL 时**临时分配**的，重启电脑、`wsl --shutdown`、
WSL 空闲被回收后再唤醒，都可能变。而 portproxy 规则里那个地址是**写死的**，
不会跟着变。于是：WSL 里 `curl 127.0.0.1:8010` 一切正常、服务 `active`，
但同事全都连不上。

**已经自愈**：`install_autostart.bat` 装的计划任务带 `/rl highest`，
每次登录 Windows 都会用当前 WSL IP 重写一遍转发规则。

手动确认或修复：

- 查：`deploy\deploy_check.bat` 第 [3] 项会把「当前 WSL IP」和「转发规则」并排打出来，**两者必须一致**
- 修：重跑 `deploy\deploy_setup.bat`（管理员），或注销后重新登录 Windows

**可选的一劳永逸办法**：改用镜像网络。新建 `C:\Users\<你的用户名>\.wslconfig`：

```ini
[wsl2]
networkingMode=mirrored
```

`wsl --shutdown` 后生效。镜像模式下 WSL 直接共享 Windows 网卡，
**portproxy 整个不需要了**（防火墙规则仍要留）。需要 Windows 11 22H2+。

### 第二种：Windows 这一侧的地址也会变

同事访问用的是 **Windows 的内网地址**，它同样是路由器 DHCP 发的，一样会漂。
2026-10-08 就发生过一次：本机从 `192.168.2.102` 变成 `192.168.2.106`，
旧地址随即被发给了局域网里**另一台设备**。这种故障最有迷惑性——WSL 里服务正常、
`deploy_check.bat` 第 [3] 项（WSL IP 与转发规则）也全对，但同事按旧地址访问时，
请求根本没到这台机器，他打开的是**别人的电脑**，浏览器只会报"无法访问"。

- 查：`deploy\deploy_check.bat` 第 [4] 项打印的，就是**现场探测到的当前内网 IP**。
  `deploy_setup.bat`、`start.sh` 的提示也已改成动态探测，不再写死地址。
- 修：把新地址告诉同事即可。想根治就在路由器管理页给本机网卡 MAC 做
  **DHCP 地址保留**（或改静态 IP）——否则路由器重启、换网线都可能再漂一次。
- 同网段内漂移不影响防火墙规则（`remoteip=192.168.2.0/24` 按网段放行）；
  若整机换到别的网段，防火墙规则的 `remoteip` 要跟着改。

## 五、改口令（强烈建议）

```bash
cd /mnt/d/数据审核归档平台
python3 -c "
from app.infra import auth
auth.set_password('换成你的新口令')          # 至少 6 位
print('已改，所有人需要重新登录')
"
```

改口令会顺带换掉会话密钥，**所有已登录的人立即掉线**。
想同时改用户名：`auth.set_password('新口令', '新用户名')`。

口令**不写在任何脚本里**（隔壁平台是 `start.sh` 里 `export DEPLOY_PASS=`，
这里没有对应的一行，别去找）。

## 六、开机自启的两种粒度

`install_autostart.bat` 装的是 **Windows 登录时** 启动 —— 你得登录一次 Windows。
想让它在**开机、还没人登录**时就起来，再执行一次（要管理员口令）：

```bash
sudo loginctl enable-linger cx
```

配合任务计划里加一条开机运行 `wsl.exe -d <发行版名> true` 把 WSL 拉起来。
一般用不上，登录时启动够用。

卸载自启：`schtasks /delete /tn AuditArchive /f`

## 七、与隔壁平台 deploy 的三处不同

| | 隔壁数据处理平台 | 本平台 | 为什么 |
|---|---|---|---|
| 进程管理 | `setsid nohup` + 按 cwd 认自己的进程再 kill | systemd 用户服务，脚本只调 `systemctl` | 这台机器上多个项目都拿 `run.py` 当入口，隔壁记着 2026-08-05 两边互相残杀的事故。systemd 只认自己启动的 PID，从根上不会误伤 |
| 口令 | `start.sh` 里 `export DEPLOY_PASS` 明文 | 配置里存 PBKDF2 派生值 | 口令不落明文文件；改口令走第五节的命令 |
| 登录方式 | HTTP Basic（浏览器弹窗） | 登录页 + 签名 cookie | 有正经登录页和「退出」按钮，会话 12 小时过期 |

### 改 deploy 目录时必须守的三条（都是实测踩出来的）

1. **`.bat` 必须是 CRLF 换行 + 纯 ASCII**。cmd 按 936 代码页读脚本、并按字节偏移
   定位下一条命令。文件里只要有 UTF-8 中文或 LF 换行，解析就会错位：`rem` 前缀被吃掉、
   注释里的字被当命令执行（报一堆 `'lick' 不是内部或外部命令`），**连 `exit /b` 都会失效**，
   脚本在"不是管理员"之后继续往下跑。要输出中文就 `chcp 65001`，
   要用中文路径就把那段命令挪进 `.sh`（如 `show_access.sh`）。
2. **`for /f` 写在 `if (...)` 块里必须用 `!VAR!`**，并在开头 `setlocal enabledelayedexpansion`。
   `%VAR%` 在进块那一刻就被展开（那时还没赋值），实测是空字符串——
   会把 `connectaddress` 设成空，转发静默失效。
3. **`wsl.exe` 默认用 UTF-16 输出自己的警告**，在任何控制台上都是乱码；
   `set WSL_UTF8=1` 让它改用 UTF-8。

改完任何 `.bat`，跑一遍确认没有 `'xxx' 不是内部或外部命令`：

```bash
echo | cmd.exe /c deploy/restart_deploy.bat        # 安全的那个，直接跑
# 会改系统的先做中和副本再验解析：
sed 's/^\(\s*\)netsh /\1echo [dry-run] netsh /' deploy/deploy_setup.bat > /tmp/dry.bat
```

## 九、服务被内核 OOM killer 杀掉（已发生过）

**症状**：界面突然一片「后台扫描中…」，审核到一半中断卡住。

**原因**：本机内存吃紧（WSL 上限 7.5GB，Windows 物理内存 15.6GB），
`opencode` 三个实例各占约 1.1GB、几个 `claude` 各占 0.3~0.4GB，加起来 4.7GB。
内核挑进程杀时看的是 `oom_score`，而 **systemd 用户管理器自身的 `oom_score_adj` 是 100，
本服务继承后也是 100**——于是只占 79MB 的它 `oom_score` 738，和 1.1GB 的 opencode（741）
并列，被连杀 3 次。

查证命令：

```bash
journalctl --user -u audit-archive --since "-1 day" | grep -i oom
systemctl --user show audit-archive -p NRestarts
cat /proc/$(systemctl --user show audit-archive -p MainPID --value)/oom_score_adj   # 100 = 有惩罚
```

**已做的缓解**：`Restart=always` + 索引快照——被杀后 5 秒自动拉起，
**重启后界面立刻可用**（108 家公司秒开，不再重扫几分钟）。日常基本无感。

**要从根上不被杀**，三选一（都需要你决定）：

1. **给 WSL 多分点内存**（最省事）。新建/编辑 `C:\Users\<你>\.wslconfig`：
   ```ini
   [wsl2]
   memory=11GB
   ```
   `wsl --shutdown` 后生效。物理内存 15.6GB，留 4~5GB 给 Windows 够用。
2. **少开几个 opencode**。三个实例 3.3GB 是最大头。
3. **改成系统级服务**（需 root）。只有特权进程才能把 `oom_score_adj` 调到 0 以下；
   用户级服务里那行 `OOMScoreAdjust=-500` **是不生效的**（留着是为了将来）。
   代价是重启要 sudo，`restart_deploy.bat` 的免管理员流程会失效，所以没默认这么做。

临时给当前进程降分（重启后失效）：

```bash
sudo choom -n -500 -p $(systemctl --user show audit-archive -p MainPID --value)
```
