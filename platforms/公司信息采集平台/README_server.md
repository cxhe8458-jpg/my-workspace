# 公司信息采集服务（局域网部署说明）

把原来的 `script.py`（单机命令行抓取）包成了一个 **Web 服务**，部署在局域网里，浏览器打开就能用。

## 一、它能干什么

1. 网页里填好 **MySQL 连接信息**（可保存、可「测试连接」）。
2. 粘贴 **官网网址**（每行一个），批量抓取，**最多 8 家并发**。
3. 抓取后自动用 **DeepSeek** 做中英互译（地址 / 概述 / 口号 / 标签）。
4. **人工审核**：逐字段对着抓取时留下的原始网页核对，错值当场修正（改动留痕、原值可还原）。
5. **只有标记「通过」的记录才会写入 MySQL**——未检和有问题的一律拦下。
6. 写入时**只新增（INSERT）**，按「官网」去重，**绝不更新 / 删除**已有数据。
7. 抓到的**原始 25 字段**会完整留档到 `runs/<时间戳>_web采集/`（JSON + Excel），一个字段不丢。

## 一·五、人工审核（2026-09-03 新增）

### 为什么必须有这一步

抓到的 25 个字段**全部由大模型从 HTML 里读出**，其中「中文名称 / 国别 / 属性 / 产品一级分类 /
产品二级分类」还是需求里的必填项。没人核对就直接进生产库，而写库又是只增不改的，
错了只能事后去库里手工收拾。所以抓取与入库之间加了一道人工闸门。

### 怎么用

浏览器打开 → 顶部切到 **「人工审核」**：

- **左侧**是本批公司清单，圆点即状态（灰=未检 / 绿=通过 / 红=有问题），可按状态筛选。
- **原网页对比面板**：点「首页原文 / 关于页原文 / 联系页原文」，或按 `W`，右侧展开**抓取当时存下来的那份 HTML**
  （已注入 `<base>`，图片样式照常加载）。
  - 它是**并排常驻面板，不是弹窗**：没有遮罩，点左侧任何地方都不会关掉它——审核就是"对着原网页改字段"，
    一点左边就把参照物关掉的话，每改一个字段都要重开一次。只有面板右上角的 `✕`（或再按 `W`）才关。
  - 面板顶部三个页签可在 首页 / 关于页 / 联系页 之间切换；那家公司没抓到的页签置灰，让人知道"就是没有"。
  - **切换公司时面板自动跟随**，不用重新点开。
  - 左边缘可拖动改宽度，开关状态与宽度都会记住。
- **两条橙色警示**会自动出现，它们直接说明这条数据有多可信：
  - 「没找到关于我们，25 个字段其实全部取自首页」——概述与分类要重点看；
  - 「没抓到联系我们」——联系方式只能来自关于页。
- **字段表**按「基础信息 / 联系方式 / 内容文案 / 业务与状态 / 系统字段」分 5 组，
  34 个字段一个不少；高风险字段标「重点」。每行三个操作：
  - `✓` 标已核对、`!` 标存疑、`✎` **改值**（原值保留，行下会显示"已修正 · 抓取原值：…"并可一键还原）。
- **抓取原始字段**（25 项）在下方只读展示：它们不入库，但「属性 / 一级分类 / 二级分类」正是必填项，
  错了要打回重抓，所以必须看得见。
- **底部结论栏**：`通过` / `有问题`（必须写说明）。标完自动跳到下一个未检的。

### 导出 Excel（连不上 MySQL 时的交付路径）

导出的**一律是审核清单里的当前值**——审核过程中改过的字段会体现在导出结果里，
不会出现"界面上改了、导出的还是旧值"。两个入口语义不同，按需要选：

| 入口 | 范围 | 用途 |
|---|---|---|
| 「人工审核」页 → **导出所选（N 家）** | 左侧清单里**勾选**的公司 | 只想导某几家时，不用每次都全量导出。勾选会记住（刷新不丢） |
| 「人工审核」页 → **导出已通过（N 家）** | 只导 `通过` 的 | 审核完毕交付、人工导库 |
| 「人工审核」页 → 导出全部 / 「采集」页 → 导出 Excel（全部） | 全部，含未检与有问题 | 存档、给别人看进度 |

**导出哪些字段可以自己选**：审核页工具条「导出字段（N/34）」打开选择框，
勾选后对所有导出按钮（所选/已通过/全部）一致生效，选择会记住。
默认排除 8 个系统维护字段（`updatedAt / updatedBy / source / createdAt / originUrl /
accessCount / check_status / type`），需要的话可以在选择框里勾回来。

**logo 下载**：审核页公司名旁的 logo 下有「⬇ 下载」按钮，下载文件名就是这家公司的
记录 `id`（方便按 id 传服务器归档）。

sheet1 前三列专门交代审核结论，方便做人工导入的人核对：

| 列 | 内容 |
|---|---|
| 审核状态 | 未检 / 通过 / 有问题 |
| 问题说明 | 标「有问题」时写的那行说明 |
| 人工修正字段 | 这条记录里被人改过的字段名（多个用「；」分隔） |

其后是 34 个 MySQL 字段，**表头直接用英文 DB 字段名**（cnName / name / website …），
人工导库时能直接对应数据库列名；「人工修正字段」列里列的也是英文名。
sheet2 是抓取的 25 个原始字段（表头同样为英文 key），与 sheet1 逐行对齐。
没有「通过」的记录时，「导出已通过」会明确拒绝而不是给你一张空表。
「导出所选」里只要有一家不是「通过」会先弹确认，说清未检/有问题各几家——
那行会照常导出并在「审核状态」列标明，不会让人拿了表才发现混着没审完的。
- 快捷键：`A` 通过、`D` 有问题、`J`/`K` 上下一家、`W` 开关原网页对比面板。

### 状态存在哪

`review_state.json`（项目根目录），**连抓取结果本身一起落盘**——刷新页面、重启服务、
换台电脑接着审，看到的都是同一份。写入用「临时文件 + 改名 + 重试 + 原地覆写兜底」，
读到损坏文件会隔离留证而不是当成空白（当成空白会让下一次保存把整批审核记录清零）。

再抓一批会**并进**现有清单；同一家公司重抓则数据换新、审核结论作废（数据都变了，旧结论不能留）。

## 二、目录结构（新增部分）

```
oe1转ps/
├── script.py               # 原有抓取核心（复用，未改）
├── server_config.json      # 运行配置（网页里保存后自动生成）
├── review_state.json       # 审核清单 + 人工核查结论（自动生成，可删=清空重来）
├── server/
│   ├── app.py              # FastAPI 入口（含审核 API 与证据文件服务）
│   ├── config.py           # 配置读写
│   ├── db.py               # MySQL 连接 + 安全写入
│   ├── review.py           # 人工审核：状态落盘、字段修正留痕、入库闸门
│   ├── mapping.py          # 25 字段 → 34 字段 映射 + 翻译规则 + 审核界面字段元数据
│   ├── translate.py        # DeepSeek 中英互译
│   ├── crawler.py          # 多线程抓取调度（复用 script.py，8 并发）+ 证据链收集
│   ├── snowflake.py        # 雪花 ID 生成（worker_id=16，与后台区分）
│   └── static/             # 前端：index.html + app.css + app.js（iOS 液态玻璃，跟随系统明暗）
├── _test_review.py         # 端到端自检（不联网、不连库）：python3 _test_review.py
└── requirements_server.txt # 后端依赖
```

## 二·五、设置页：随时换 AI 模型（2026-09-03 新增）

网页顶部「**设置**」页，数据库连接与 AI 接口都在这里。

抓取解析与中英互译**都走 AI 接口那一份配置**，改完**立刻生效、不用重启服务**
（`script.ai_config()` 按文件 mtime 读 `server_config.json` 的 `ai` 段）。
命令行单跑 `script.py` 时配置文件可以不存在，会回落到文件顶部那几个常量，两边互不依赖。

任何 **OpenAI 兼容**的 `/chat/completions` 接口都能接。下拉里预置了 10 个常见供应商，
选一个就自动填好地址、候选模型和注意事项：

DeepSeek、OpenAI、阿里云百炼（通义千问）、月之暗面 Kimi、智谱 GLM、
硅基流动、火山方舟（豆包）、OpenRouter、本地 Ollama、自定义。

| 按钮 | 作用 |
|---|---|
| 保存 | 写进 `server_config.json`，下一次抓取就用新配置 |
| 测试连接 | 真打一次接口（只发几十 token）：验地址、Key、模型名、json_mode，并报告思维链用量 |
| 拉取模型列表 | 把地址的 `/chat/completions` 换成 `/models` 去问该服务有哪些模型 |

几个字段的含义：

- **思维链 reasoning_effort**：⚠ **别乱动，保持 `none`**。推理模型的思维链**计入 max_tokens**，
  开着的话 4000+ 字符的解析提示词会把额度烧光、正文一个字都吐不出来，
  而 HTTP 仍是 200，表面上只表现为"抓取失败"。本项目是照着 HTML 填固定字段，推理没有收益。
  选「不发这个参数」适用于本身就不是推理模型的服务。
- **强制 JSON 输出**：部分服务不支持 `response_format`，关掉即可——提示词本身就要求输出 JSON，
  外层还有去 ``` 围栏与截断抢救。
- **API Key**：留空则回落 `script.py` 里的默认 Key；界面上回显为 `******`，
  保存时原样回传表示"不改"。

> 「测试连接」**不能**预测真实抓取会不会思维链烧穿：测试提示词只有一句话，
> 再爱想的模型也只烧几十 token。所以它的口径是——只要检测到思维链在用 token 就明确预警。


默认监听 `0.0.0.0:8000`——但这是**服务端的绑定地址，不是给浏览器输入的地址**。按用途选：

| 从哪访问 | 浏览器里输 |
|---|---|
| 本机 | `http://127.0.0.1:8000` |
| 局域网其他电脑 | `http://本机IP:8000`（本机当前为 `192.168.2.106`；DHCP 会变，用 `ipconfig` 查） |

> ⚠ **不要用 `http://0.0.0.0:8000`**。本机装了系统代理（Clash，`127.0.0.1:7897`），
> 绕过名单里没有 `0.0.0.0`，浏览器会把请求交给代理，代理无法路由它，直接回
> **502 Bad Gateway**。2026-10-08 实测踩过一次：启动日志打印的正是
> `http://0.0.0.0:8000`，照着输必然 502（不是服务没起来）。

局域网访问还需要防火墙放行 8000。已加规则 `CompanyInfo-8000`（只放行 `192.168.2.0/24`，
与另外两个平台的 `DataPlatform-8688` / `AuditArchive-8010` 同口径）；换机器部署时重建：

```
netsh advfirewall firewall add rule name="CompanyInfo-8000" dir=in action=allow protocol=TCP localport=8000 remoteip=192.168.2.0/24
```

## 六、安全说明（重要）

- **入库闸门：只写人工标了「通过」的记录**，未检与有问题的一律不写。
- **只 INSERT，不 UPDATE / DELETE / TRUNCATE**。
- 字段白名单 + 参数化查询（防注入）。
- 按「官网」去重，已存在自动跳过，**不会覆盖**。
- 「测试连接」只读，不触发任何写操作。
- 写库前网页会弹二次确认。

## 七、常见问题

- **连不上 MySQL**：确认服务器 IP/端口、账号密码；MySQL 需允许局域网访问（`bind-address` / 防火墙 3306）。
- **密码是 `caching_sha2_password`**：已装 `cryptography` 依赖，一般能自动处理。
- **端口被占用**：改 `server/app.py` 末尾的 `port=8000`。


## 八、改了代码之后

- **改后端必须重启服务**（路由在进程启动时加载）：关掉 `start_server.bat` 的窗口再双击一次。
  重启前先确认没有残留进程占着 8000 端口（2026-09-02 踩过：残留 uvicorn 与新实例抢端口 → 502）：
  `netstat -ano | findstr :8000`
- **改前端（`server/static/` 下的三个文件）不用重启**，普通刷新即可——静态资源已全局禁缓存。
- **改完跑一遍自检**：`python3 _test_review.py`（临时目录造数据，不联网、不连库、不碰真实文件）。
  它覆盖鉴权、审核清单、字段元数据完整性、结论标记、人工修正与还原、入库闸门、
  证据服务与路径穿越、静态资源、导出、状态落盘与坏文件隔离。
