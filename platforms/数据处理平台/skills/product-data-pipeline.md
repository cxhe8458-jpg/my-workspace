# product-data-pipeline —— 产品数据处理全流程（agent 执行手册 v1.0）

本手册供 **agent 照着自动执行**。铁律贯穿全程：**原始数据零改动、全程可回退、任何合并/删除前先确认能从原始恢复、每步后立即校验、不通过不进入下一步**。

脚本目录（下称 `$SC`）：`~/.claude/skills/product-data-pipeline/scripts/`
> 内含：`engine.py split.py id_rename.py consolidate.py merge_all.py classify2.py audit2.py verify.py`
> `merge_all.py / classify2.py / audit2.py` 顶部有 **CONFIG 块**（BATCHES/路径），跨环境时先按实际改这几行。

## 0. 总览与前置

### 0.1 五步流程与数据流向
```
原始爬取数据  整体数据X/<公司中文名>/<厂商原大类>/<产品>/(info.json,主图.jpg,参数图_N.jpg,说明书.pdf,description.txt…)
  ①字段映射   engine.py   → 产品映射/<公司>/<cat1>/<cat2>/<产品>   + 未分类/<原大类>/…
     拆分     split.py    → 产品映射/{产品已映射,产品未映射}/<公司>/…
  ②公司名→id  id_rename.py→ …/<id>/…                       （公司id.json 外部维护, 实时读）
  ③合并       consolidate.py→ <产品>/<产品名>.json + <产品名>.pdf(+_N.pdf)
     跨批次合并 merge_all.py→ 待分类/{产品已映射,产品未映射}/<id>/…
  ④二次分类   classify2.py→ 待分类/二次分类/{类别1_json_非空,类别2_pdf,类别3_json_空}/<id>/…
  ⑤复查       audit2.py   → 逐产品页数核对, 全批次损失=0
```

### 0.2 目录与命名约定（先探明再动手）
- **批次**：`整体数据`(基准,无后缀) 与 `整体数据1..4`，各自独立、config 不共享。
- 每批次：`产品映射/{_config, _scripts/engine.py}`；`产品映射/<公司中文名>`＝拆分前完好副本(pristine)。
- ⚠ **拆分位置历史不统一**：有的批次 `产品已映射/产品未映射` 在**批次根**，有的在 `产品映射/` 内。**动手前必须先 `ls` 探明实际位置**：
  ```bash
  for b in 整体数据 整体数据1 整体数据2 整体数据3 整体数据4; do
    echo "== $b =="; for p in "产品已映射" "产品映射/产品已映射"; do [ -d "/mnt/d/公司数据备份/$b/$p" ] && echo "  有: $p"; done
  done
  ```
- 最终产物：`待分类/{产品已映射, 产品未映射, 二次分类/类别1|2|3}`。

### 0.3 公司id对照表（外部、不定期更新）★
- `公司id.json` 是**外部维护、会不定期新增公司**的文件。**每次用到都实时读取**，不要把内容写死进脚本/流程。
- 结构：`[{"id":"…","cnName":"…"}, …]`。所在路径以运行时实际为准（常见：某批次 `产品已映射/公司id.json`）。
- **未收录的公司** → 跳过、保留中文名，并**明确告知用户去补 json 或提供 id；不确定就问，绝不臆测 id**。

### 0.4 依赖环境（先装齐）
```bash
python3 -m pip install --break-system-packages -q pypdf img2pdf Pillow pikepdf cairosvg
python3 - <<'PY'
import pypdf,img2pdf,PIL,pikepdf,cairosvg; print("deps OK")
PY
```
> ⚠ pip 受 PEP668 管理，必须 `--break-system-packages`（或用 venv）。`/mnt/d` 是 Windows NTFS，**大小写不敏感**——多处埋雷（见③⑤）。大批量一律**后台运行 + 多线程**。

## 步骤① 字段（分类）映射 —— `engine.py`
把每个产品按 **产品名 + 父级目录**（不看描述）映射进 12 大类/162 子类标准树。规则详见 skill `product_category` 与 `product-folder-standardizer`；本步只讲操作。

### 操作
```bash
cd "/mnt/d/公司数据备份/<批次>/产品映射/_scripts"
python3 engine.py "<公司全称>"            # dry-run: 只打印分布/未分类/泛词, 不动文件
# 审阅后 → 增补 _config 双语关键词 / 写 研判归类_<公司>.json、未匹配说明_<公司>.json
python3 engine.py "<公司全称>" --apply     # 复制落地 + 生成 映射报告.md
```
判定顺序：Part-2 硬规则 → 产品名(Stage A) → 父级逐级退回(Stage B) → **研判归类(AI兜底)** → 未分类。

### 易错点
- **ROOT 路径**：`engine.py` 从脚本位置自动推导批次根，勿写死。
- **新增关键词 confidence 必须 ≥0.90**，否则被 Stage A/B 阈值丢弃。
- **晶体二次分流 bug**：`eng_norm(中文)` 会塌缩成空串，纯中文晶体名会被误升“激光晶体”——中文关键词用 `nospace` 子串、英文用词边界(`eng_hit`)。
- **同名叶子冲突**：不同源产品同名落到同一分类会互相覆盖 → 引擎已加消歧(后到者叶子追加 `（源_原大类）`)。
- 应用/服务 mapping 不参与产品分类；“仪器 vs 部件”“型号前缀泛词(AP/VR/PLC…)”等陷阱见 `product-mapping-workflow-gotchas`。
- ★**AI 研判归类**：对 mapping 未命中、需 AI 研判的产品，**必须用产品的完整路径名(公司/大类/[子类/]产品名)去查证它到底是什么**（本地 info/description/参数/URL，必要时联网核实型号），确认定义后再映射进**已存在**的合法 category；查不到真实归属就保留未分类、据实说明，**不硬塞、不臆造**。研判结果写入 `研判归类_<公司>.json`（含依据），置信度记 0.90，报告单列一节供复核。
- 复查：未分类必须**逐条据实**说明，`待补=0` 才交付。

### 拆分（① 后半）—— `split.py`
```bash
python3 $SC/split.py "/mnt/d/公司数据备份/<批次>/产品映射"        # 输出到 产品映射/ 内
# 若该批次约定放批次根: 加 --dest "/mnt/d/公司数据备份/<批次>"
```
- 复制不移动；`产品已映射`=cat树(+映射报告.md)；`产品未映射`=**去掉“未分类”这层**，还原 `原大类/[原子类/]产品`。
- 校验：`原产品映射 info.json 数 == 已映射 + 未映射`。

## 步骤② 公司名 → id 替换 —— `id_rename.py`
只改**公司文件夹名**（中文→数字id），内容/结构不动。范围：`产品已映射` + `产品未映射`。

### 操作
```bash
IDJSON="/mnt/d/公司数据备份/<批次>/产品已映射/公司id.json"    # 实时读, 路径以实际为准
# 1) dry-run 看匹配/未解析
python3 $SC/id_rename.py --idjson "$IDJSON" \
   "/mnt/d/公司数据备份/<批次>/产品已映射" "/mnt/d/公司数据备份/<批次>/产品未映射"
# 2) 确认后 --apply
python3 $SC/id_rename.py --idjson "$IDJSON" --apply \
   "/mnt/d/公司数据备份/<批次>/产品已映射" "/mnt/d/公司数据备份/<批次>/产品未映射"
```
### 易错点
- **名称记揺れ**：全角/半角括号、`股份↔有限`、简称↔全称、英文名、日文社名、错别字(如 智行↔智兴)。脚本用 **NFKC 归一 + override 表**处理；仍未解析的**必须问用户/查证，别猜**。新变体用 `--override "中文名=id"` 或补进脚本 `OVERRIDE`。
- **文件被占用** → `PermissionError`（Windows 资源管理器/预览器打开了该文件夹）。关掉后重试即可。
- **幂等**：已是数字 id 的自动跳过；可安全重跑。
- 校验：目标目录下公司文件夹**全为数字 id**、可反查中文名、无遗漏；未解析清单为空(或都是已知待补)。

## 步骤③ 参数图/主图/说明书PDF 合并 —— `consolidate.py`
每个产品折叠为 `<产品名>.json` + `<产品名>.pdf`。范围：仅 `产品已映射`（`产品未映射` 保持原样、不合并）。

### 两个子操作
- **操作1(json)**：有 `description.txt` → 内容并入 info.json 的 `产品描述` → 删 txt；**所有产品**把 `info.json` 改名 `<父文件夹名>.json`。
- **操作2(pdf)**：★**牢记：先把主图/参数图各自转成 PDF，再在最终 PDF 的“顶部/最前面”合并**。顺序 = `主图*` → 其他产品图(型号名图/图片*) → `参数图*` → 原说明书PDF。多PDF：图片并入第一个为 `<父名>.pdf`，其余原PDF改名 `<父名>_N.pdf`。生成后**删除原图片和已并入的原PDF**，只留 json+pdf(+_N.pdf)。

### 操作
```bash
# 破坏性! 先小样验证(见下), 再全量后台跑
python3 $SC/consolidate.py "<产品已映射根>"           # dry-run: 只统计, 不改
python3 $SC/consolidate.py "<产品已映射根>" --apply   # 落地; 大批次用 run_in_background
```
样本验证（改动前，务必先做）：把含各情形的几个产品复制到临时目录 → 在临时目录 `--apply` → 检查 `<父名>.json` 有“产品描述”、`<父名>.pdf` 页数 = 图片数+原PDF页数 → 再对真实目录跑。

### 易错点（本流程最大雷区）
- ★**原PDF名 = 产品名（含仅大小写不同）**：`/mnt/d` 大小写不敏感，`cdtrans-1000.pdf` 与 `CDTrans-1000.pdf` 是同一文件；合并生成 `<父名>.pdf` 后“删除原PDF”会把**刚生成的PDF自己删掉**，只剩 json。→ 删除守卫用**小写比较**：`abspath(p0).lower() != abspath(final).lower()` 才删。（consolidate.py 已修）
- ★**SVG 伪装成 .jpg**：内容是 `<?xml`/`<svg>` 的矢量图，img2pdf/PIL 报 `UnidentifiedImageError`。→ 先探测 SVG，用 **cairosvg svg2pdf** 转换合入，**别丢弃**。（已修）
- **无效/损坏图片**：img2pdf 与 PIL 均失败 → 返回 None **跳过该图**，勿让整个产品报错。
- **全部图片无效 → 0 页 PDF**：不生成PDF、只留 json，不抛异常。
- **必须包含全部图片**：历史坑是“只转主图、丢弃参数图/其他图”。order = 主图* → 其他 → 参数图*，一个不落。
- **破损原PDF**：pypdf 读不了 → 用 **pikepdf** 修复后合并；修复不能 → 退化为“图片-only PDF”，原文件在 pristine 仍在。
- **重跑前先 `rm -rf` 该公司/产品目录**再 `--apply`，否则分类/多PDF变更时旧副本残留、同名冲突。
- 校验：残留 `info.json`/`description.txt`/`.jpg` = 0；无 `.__*` 临时文件；每产品有 `<父名>.json`。

## 步骤④ 二次分类（三类） —— `merge_all.py` + `classify2.py`
不改原数据/结构，**另建**分类视图，用**复制**（此环境无法从 WSL 建 Windows .lnk 快捷方式）。

### ④a 跨批次合并到 待分类 —— `merge_all.py`
把 5 批次的 `产品已映射` + `产品未映射` 汇总到 `待分类/{产品已映射,产品未映射}/<id>/…`。
```bash
# 编辑 $SC/merge_all.py 顶部 ORDER(各批次 已/未映射 路径) 与 DEST, 然后:
python3 $SC/merge_all.py          # 后台跑; 末尾有 files exp==got 核对
```
- **未分类单独**：`产品未映射` 归 `待分类/产品未映射`，**绝不与已分类混**（若曾误把已/未混入同一目录，须停下重做：分离到两个子目录）。
- **重复公司去重**：个别“试点”公司(如 拓姆泰克/福晶/易飞扬)在多批次都有且产品数不同 → **首批(基准 整体数据)优先、只留产品最全的版本**（merge_all 用 first-batch-wins）。
- 校验：`files exp == got`、`产品已映射 info/父名json 计数正确`。

### ④b 三类分类 —— `classify2.py`
```bash
python3 $SC/classify2.py "<待分类/产品已映射>"           # dry-run: 三类计数
python3 $SC/classify2.py "<待分类/产品已映射>" --apply   # 多线程(16)复制到 二次分类/类别X/<id>/<原相对路径>/<产品>
```
三类定义：
| 类别 | 条件 |
|---|---|
| `类别2_pdf` | 有 PDF |
| `类别1_json_非空` | 无 PDF 且 **参数非空**（看 `产品参数`/`参数信息`/`产品规格`；顶层实际是 `参数信息` 或 `产品参数`(内含 说明/规格)；空 = `{}`/`[]`/空串） |
| `类别3_json_空` | 无 PDF 且 参数为空 |

### 易错点
- **参数字段不统一**：`参数信息`(主) 与 `产品参数`(少, 互斥, 内含规格)。判定要覆盖两者，任一非空即“非空”。
- **移动/重分类后删空目录**：`find <类别目录> -depth -type d -empty -delete`。
- copytree 目标已存在需先删；先 dry-run 出三类计数再 `--apply`。
- 校验：三类计数之和 = 总产品数；`类别2` 全有PDF、`类别1/3` 全无PDF；原 `产品已映射` 未改。

## 步骤⑤ 数据复查（审计） —— `audit2.py`  ★务必准确的最后防线
逐产品核对 **原始(图片数 + 原PDF页数)** vs **合并后PDF总页数**，`got < 期望` = 丢失。

### 操作
```bash
# 编辑 $SC/audit2.py 顶部 BATCHES(各批次: consolidated根, pristine根, 类型) 与 IDJSON, 然后:
python3 $SC/audit2.py 2>/dev/null      # 后台; 输出各批次“损失N”, 目标全为 0
```
### 匹配键（关键，别搞错）
- **path-aligned 批次**(pristine=`产品映射/中文`, 与已映射同结构)：按**相对路径**匹配（精确）。
- **raw 批次**(pristine=批次根原始, 结构不同)：按 **公司id + 产品名(叶子)** 匹配。
- ★**绝不能用 `页面URL` 当匹配键**：很多是分类**列表页**URL、被多个产品共用 → 造成大量误报（曾把单个多-PDF产品误报成多处损失）。

### 易错点
- 期望页数里若含 **SVG/无效图**，会虚增期望 → **先确保 ③ 已正确处理这些图**，否则审计会假报损失。
- pypdf 对轻微破损 PDF 刷大量 stderr 警告 → `2>/dev/null` 或降 log level。
- 破损 PDF 读不到页数按 0 计，注意别误判。

### 修复闭环（发现损失时）
1. 逐条拿到 (consolidated目录, pristine源目录)。
2. **清空** consolidated目录 → 从 **pristine 复制原始文件** → 用**修正版 `consolidate.py`** 重建。
3. 重跑 `audit2.py` 直到**全批次损失 = 0**。
4. 重新 `merge_all.py`(待分类) + `classify2.py`(二次分类) + 清空目录，使下游同步。

## 附录 B：易错点速查（top pitfalls）
1. `/mnt/d` **大小写不敏感** → ③ PDF名=产品名(大小写)误删生成物；去重/删除守卫要小写比较。
2. **SVG/无效图**伪装 .jpg → ③ 用 cairosvg 转/安全跳过；⑤ 会虚增期望。
3. **重跑前不清目录** → 残留/同名冲突（②③④都要先清）。
4. 分类关键词 **confidence < 0.90** 被丢弃；晶体分流 eng_norm 塌缩 bug。
5. 审计**误用页面URL**匹配 → 大量误报；应按路径 / 公司+产品名。
6. 公司名**记揺れ**匹配（NFKC + override + 问用户）；`公司id.json` **外部实时读**。
7. **AI 研判**必须用**完整路径名查证定义**后再映射，不硬塞。
8. **③ 合并**：先把主图/参数图转成 PDF、再在**顶部**并入；必须含全部图片。
9. **未分类必须与已分类分离**。
10. 每步后立即校验（md5/计数/页数）、全程可回退。
