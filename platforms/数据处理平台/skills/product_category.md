# product_category — 公司产品分类映射规范（已对齐版）

本 skill 记录对本仓库 `/mnt/d/公司数据备份/整体数据/` 执行**产品分类映射**时**必须遵守**的、
我们已逐条对齐的补充要求。分类判定逻辑沿用 `product-folder-standardizer` 技能（规则/优先级/
Part-2 硬规则），本 skill 只固化“怎么落地、放哪里、不许动什么、报告怎么写”。

## 0. 前置：分类判定引擎
- 分类规则以 `product-folder-standardizer`（config 在 `~/.config/opencode/skills/product-flider-standardizer/config/`）为准：
  规则优先于 AI；**分类路径 > 产品名 > 描述**；最长关键词优先；Part-2 硬规则覆盖普通 mapping；
  输出 `category1/category2` 必须存在于 `company_categories.json`（12 大类 / 162 子类）。
- 已实现的引擎：`产品映射/_scripts/engine.py`
  - `python3 engine.py "<公司全称>"`       → 干运行（dry-run），只打印分布与未分类，不动文件
  - `python3 engine.py "<公司全称>" --apply` → 复制落地 + 生成 `映射报告.md`
  - **务必先 dry-run 审阅，再 --apply。**

## 1. 落地位置与目录结构（强制）
- 在仓库根同级新建并使用 `产品映射/` 文件夹，做过映射的公司放里面。
- 命中分类：`产品映射/<公司全称>/<category1>/<category2>/<产品>/`
- **复制，不移动**：原始 `<公司全称>/…` 目录**原封保留**（可回退）。
- 统一树固定为 **`公司/category1/category2/产品`**（三级 + 叶子）。

## 2. 数据零改动（强制，最重要）
- 任务**只改分类层级**（即产品叶子的父路径），**不得修改产品叶子内任何数据**：
  `info.json`、图片(JPG)、PDF 全部**逐字节原样复制**。
- **叶子产品文件夹名完全不变**。
- **不新增字段**：`info.json` 保持原样（`上级名称` 等一律不改），保证可追溯。
- 落地后应做完整性校验：原始 vs 映射 的文件内容多重集必须一致（md5 集合相等），info.json 数量一致。

## 3. 未分类产品处理（强制）
- 无双语关键词命中，或置信度 `< 0.90` → 判为 **未分类**（需人工复核）。
- 存放：`产品映射/<公司全称>/未分类/<原大类>/[<原子类>/]<产品>/`
  —— 即在**原分类级别前加一层 `未分类/`**，保留其原有层级，不丢失原始归属。
- 未分类产品**必须在报告中逐条写明原因**。

## 4. 双语映射配置（强制）
- 匹配前，`product-folder-standardizer` 的每个 `mapping_*.json` 关键词都要有**中/英两种语言**。
- 本仓库的双语副本在 `产品映射/_config/`：每条形如
  `"English Keyword": {"zh":"中文标准译名", "category1":"…","category2":"…","enable":true,"confidence":…}`。
  全局 skill 的 config **不改动**，只在仓库内维护双语副本。
- 翻译要求：站在**光电产品专家**视角，做**最精确、最标准**的中文译名（直接影响中文名产品的匹配）。
- 扩充（README §17 允许）：可为**已存在的 category2** 增补中文同义词/牌号关键词以提升召回，
  但**严禁新建/改名/翻译分类**，也**禁止**改动置信度或忽略精确 mapping。

## 5. 跨类子类统一（强制约定）
- `光纤检测工具`、`光纤测试与测量` 这两个子类**只归于 `测试和测量`**（不再挂在 `光纤元件` 下）。
- 引擎中以 `UNIFY` 映射实现；后续所有公司一律按此级别执行。

## 6. 每家公司映射报告（强制）
- 路径：`产品映射/<公司全称>/映射报告.md`（每做一家就生成一份）。
- 必含内容：
  1. **总览**：产品总数 / 已映射数（含泛词命中待确认数）/ 未分类数 / 目标结构说明。
  2. **映射分布**：`category1 / category2 → 数量`。
  3. **逐产品明细表**，格式对齐：
     `原分类路径(原大类/[原子类/]原产品) + 携带文件(info.json/图片/PDF) → 现分类(cat1/cat2) + 命中关键词 + 置信度 + 备注`。
  4. **未分类清单及原因**（逐条）。
  5. **建议人工确认**：泛词命中的条目单列，供复核。泛词＝中文 ≤2 字（“光纤/光缆/光源/物镜”）
     或英文跨域同名通用词（`Adapter/Mount/Base/Post/Clamp/Housing/Package/Tool/Module/Cable/Card…`）。

## 6.1 规则1 —— 父级退回继承（强制）
产品优先用**自身产品名**匹配；**产品名匹配不上时才启用退回机制**，退回到父级目录用目录名匹配。
- **顺序**：Part-2 硬规则 → **Stage A：产品名** → **Stage B：父级逐级退回** → 未分类。
- **Stage B 退回深度**：从**紧邻父目录逐级向上到大类**，对每级目录名单独匹配，取**最先命中（最具体）**的一级。
- **继承**：父级某层命中后，产品**继承**该层的 `category1/category2`，**置信度取父级原值**，
  备注标注“**继承自父级目录《X》命中《关键词》**”，直接进标准树 `公司/cat1/cat2/产品`（不进未分类）。
- **为何产品名优先而非路径优先**：大类目录常是宽口径桶（如“Coherent Optical Modules & DCI BOX”），
  若路径优先会把 EDFA/OTDR 卡等一并误吞为“发射器和接收器”；故按规则1字面“匹配不上才退回”＝产品名优先，
  父级仅作兜底，既保精度又能让纯型号名产品经父目录继承归类。
- 英文匹配做**单复数容错**（Transceivers↔Transceiver，product-folder-standardizer 归一化要求）。

## 6.2 规则2 —— 未匹配必须据实说明（强制）
每个最终未匹配（含**父级退回也失败**）的产品，都要有**针对该产品、据实**的原因，**禁止套用笼统模板**。
- 原因由人工逐条查看该产品实际信息后手写（plan b），维护在
  `产品映射/_config/未匹配说明_<公司全称>.json`（键＝原路径 `大类/[子类/]产品`，值＝原因）。
- 原因应写明：该产品**实际是什么**、**为何未命中**（缺牌号关键词／中文词形差异如 镜↔透镜、器↔镜、窗片↔窗口片／
  分类树无对应子类等），并在有明显近似时给出**最接近的候选子类**。
- 报告生成时读取该文件；若某条缺说明，报告会标“待补人工据实说明”并计数——**必须补齐至 0 条**再交付。

## 6.3 规则3 —— 未匹配产品的“研判归类”兜底（强制，AI Second）
经 Part-2 → 产品名 → 父级退回**全部失败**后，**不要直接丢进未分类**：agent 需**主动查阅研判**该产品到底是什么，
归入正确的 category，并**明确标记**为“研判归类”（区别于 mapping 关键词命中），供人工复核。
- **触发位置**：判定流程的**最后一层兜底**；**不得覆盖**已由 Part-2/产品名/父级退回命中的结果。
- **查阅信息源**：产品本地数据（info.json / description.txt / 参数 / 主图名 / 页面URL）+ 光电专业知识；
  本地不足时**允许联网检索**（产品页 URL / 型号）辅助研判，但**严禁凭空捏造**，须有据可依。
- **目标约束**：研判结果必须是 `company_categories.json` 内**已存在**的 `category1/category2`（不得新建/改名），
  且遵守统一子类规则（光纤检测工具/光纤测试与测量→测试和测量）。
- **确无合适子类**（如温控炉、DAC 铜缆、SDI 视频光端机等分类树未覆盖者）→ **仍保留未分类**（按规则2据实说明），不硬塞。
- **落地与标记**：研判归类的产品**照常进标准树** `公司/cat1/cat2/产品`；置信度记 **0.90**；
  结果维护在 `产品映射/_config/研判归类_<公司全称>.json`（键＝原路径，值＝`{category1, category2, 依据}`）；
  **不改 info.json**；报告中**单列一节“研判归类（AI 研判兜底，需复核）”**，逐条给出 现分类 + 依据。
- 引擎读取该文件作为最后兜底：命中则进标准树并标 `研判归类(AI研判)`，否则才落未分类。

## 7. 分类判定要点（继承 product-folder-standardizer，勿违背）
- **产品 > 应用 > 服务**：本仓库是**产品**仓库，`mapping_application.json` / `mapping_service.json`
  **不参与**产品分类（避免“科研教育/通信与能源”等应用词误吞产品）；只在确无产品域命中时才考虑，
  当前实现为直接不参与 → 归 `未分类`。
- **描述不参与分类**：主分类只用 `产品名 + 父级目录名`（见规则1）；`产品特性`/描述字段**不参与**，
  以免“测量仪→灯具/配件”这类误判。
- **晶体二次分流**：增益晶体（YAG、Ti:Sapphire、掺钕/铒/镱…、激光/增益晶体）→ `激光晶体`；
  非线性/电光/声光晶体（BBO、LBO、KTP、PPLN、LiNbO3、KDP…）→ `晶体`。
- **判定顺序（总）**：Part-2 硬规则 → 产品名 mapping → 父级逐级退回继承 → **研判归类(AI兜底)** → 未分类。
- **确定性**：mapping/规则层同一输入永远同一输出；研判层为 AI 兜底，须标记且可复核，不臆造、不新建分类。

## 8. 标准执行流程
1. 加载 `product-folder-standardizer`（拿分类规则与 config）。
2. 确认 `产品映射/_config/` 双语 mapping 完备（12 文件，全部关键词有 `zh`）。
3. `engine.py "<公司>"` 干运行，人工审阅分布、未分类、待确认（泛词）项。
4. 必要时增补 `_config` 的中文同义词（只对已存在 category2），重跑干运行。
5. **规则2/规则3**：对未命中产品，先由 agent 研判——能归入合法 category 的写入
   `产品映射/_config/研判归类_<公司>.json`（进标准树、标“研判归类”、置信度0.90+依据）；
   确无归属的保留未分类，并在 `产品映射/_config/未匹配说明_<公司>.json` 逐条据实写原因（补齐至 0 条待补）。
6. `engine.py "<公司>" --apply` 落地复制 + 生成 `映射报告.md`。
7. 完整性校验（文件多重集 md5 相等、info.json 计数一致；未分类按原级别归档）。
8. 交付：`产品映射/<公司>/`（新树）+ `映射报告.md`，供审阅。

## 9. 已完成试点（参考基线）
- 福建福晶科技股份有限公司：86 产品，已映射 49，未分类 37，待确认 7（中文/晶体·光学）。
- 深圳市易飞扬通信技术有限公司：167 产品，已映射 131，未分类 36，待确认 3（英文/光纤·通信；
  规则1 父级继承 + 单复数容错使召回由 123→131）。
- 已知问题（供后续优化）：中文命名产品召回偏低，主因“镜/器/镜片、窗片/窗口片”形态差异与专用晶体牌号缺关键词；
  解决方向＝为已存在 category2 增补标准中文同义词（不新增分类）。
