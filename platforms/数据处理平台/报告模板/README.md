# 报告模板样图 —— 三个角度

## 怎么看

直接双击三个 HTML，或者重新生成（读的是当前真实数据，随时可刷新）：

```
cd D:\自动化数据处理\数据处理平台
python3 报告模板\generate.py
```

三份都是自包含单文件，零外部请求，断网、发给别人、打印都能用。

## 三份的分工

不是同一份换皮，是三个不同的问题：

| | 回答什么 | 分母 | signature 图 |
|---|---|---|---|
| **A 分类覆盖** | 哪里还是空的 | 标准体系 160 个二级分类 | 覆盖矩阵（12 行 × 二级分类格子） |
| **B 公司覆盖** | 数据靠谁撑着 | 232 家公司 / 20345 个产品 | 帕累托累计曲线 |
| **C 周期进展** | 这周干了什么、质量往哪走 | 按周（六→五） | 产量柱 + 未匹配率折线 |

## 每份里真正的发现

样图用的是 2026-08-14 的真实数据，不是占位符。三份各自挖出来的东西：

**A 分类覆盖**
- 二级分类覆盖 **148/160 = 92.5%**，12 个完全空白
- 缺口极不均匀：`行业应用与系统` 只覆盖 6/10 且整类只有 33 个产品；
  而 `测试和测量` 有 2626 个产品却缺 4 个二级分类 —— 后者更值得优先补
- 表里把这两种情况分开标了「整类都薄」和「该类有量，独缺此项」
- **发现一个真问题**：`成像/虚拟现实` 不在标准体系里，标准体系写的是
  `成像/虚拟现实增强现实` —— 同义词被当成了新类，会让覆盖率既算不准也对不齐

**B 公司覆盖**
- 强帕累托：**前 21 家（9%）撑起一半产品，前 79 家（34%）撑起 80%**
- 89 家（38%）高度专精（单一大类 ≥90%），27 家是不足 10 个产品的长尾
- 结论写在旁注里：复核资源应该按这条曲线分配，不该按公司数平均分

**C 周期进展**
- 本周 84 家 / 6341 个产品，比上周 +26 家 / +2312 个
- **未匹配率五周从 10.6% 降到 2.8%** —— 这是最值得写进周报的一条
- 但本周成功率比上周降了 1.1pt、未匹配率升了 1.2pt，涨跌都标了色（升不一定是好，
  未匹配率的涨跌是反着判的）

## 设计上的取舍

沿用 frontend_v3 那套（Tufte / 编辑部）：零卡片、细横线分区、等宽小字大字距做标签、
衬线只给标题和大数字。**图表色板 `--d1..--d8` 和状态色语义原样保留**，一个色值没改。

几个具体决定：

- **覆盖矩阵用对数分档上色**，不是线性 —— 线性的话 5450 和 33 挤在一起，
  除了最大的那几格全是白的，矩阵就废了
- **空白格用虚线描边而不是填浅色** —— "没有"和"很少"必须一眼分得开
- **百分比条不再算"占比"**：第一版我拿百分比去除以百分比之和，得出 9.2% 这种没意义的数，
  已改成只显示值本身
- **折线标签描白边**：未匹配率的点会落到实心蓝柱上，橙字压蓝底看不清

## 如果要并进平台

`backend/htmlreport.py` 现在是一份报告（`build_html`）。要落地的话：

1. 把 `generate.py` 里的 `CSS` / `metrics` / `bars` / `stack` / `figure` 搬成公共件
2. `ExportReq` 加一个 `template: "a"|"b"|"c"` 字段，导出面板加个选择器
3. C 模板天然接刚做完的周期功能 —— 它本来就是"每周五那份"
4. A/B 两份不需要周期参数（是全量视角），C 需要

工作量估计：公共件 + 三个 builder 并进去约 600 行，报告是新增的输出，不影响平台本身跑。

## 没做的

- 三份都是静态的，没有老报告那种「选一家公司，图表跟着变」的下钻交互
  （老报告那套 JS 可以直接搬过来，只是样图阶段先不做）
- AI 分析段落没接（老报告有，位置留着就行）
- 没做打印分页优化，只加了 `break-inside:avoid`
