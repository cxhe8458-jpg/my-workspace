## 从参考页借了什么

参考：kimi.page《推理芯片的四十二年》。它的设计语言是 **Tufte / 编辑部排版**，四个特征：

| | 参考页的做法 | 现在的平台 |
|---|---|---|
| 分区 | `border-top: 1px` 一条细线 | 圆角卡片 + 阴影 + 填充块 |
| 字体 | 衬线体（et-book）通排 | 无衬线（PingFang / 雅黑） |
| 标签 | 等宽小字 + `letter-spacing:.26em` | 常规小字 |
| 强调色 | 单一电光蓝 `#2251ff` | 墨黑 `#14181d` + 靛 `#23408e` |
| 底色 | 纯白 `#fff` | 微冷灰绿 `#eff1f0` |

样图把这四条都搬了过来：零圆角零阴影、章节号用 `01 / 构成` 这种等宽大字距标签、
指标块只有一条上边线、表格只剩横线。

## 刻意没动的两件事

原 `style.css` 开头立了条规矩：「屏幕上出现的任何饱和色都必须有含义」。样图守住了：

1. **状态色语义不变** —— `ok/warn/err/ai` 四个色值原样保留，只是把胶囊底色换成了小方点 + 文字
2. **图表色板 `--d1..--d8` 一个色值都没改** —— 那是过了 `dataviz validate_palette.js` 校验的

## 跟参考页不一样的三处（都是被迫的）

### 1. 字体拆成两支，不是通排衬线

参考页整页 et-book。但那套字要下载字体文件，且中文会落到宋体系 —— **Windows 上只有
SimSun**，14px 以下的表格文字会发虚，粗体靠合成涂抹（我在 Linux 上截图时就撞见了）。

所以拆开：
- **衬线**（`Source Han Serif SC` → `Noto Serif SC` → `Songti SC` → `SimSun`）：h1/h2/h3、
  大指标数字、图表标题、导语 —— 气质来源
- **无衬线**（`PingFang SC` / `Microsoft YaHei`）：表格、说明文字、正文 —— 密集小字的清晰度

零外部字体请求，不下载任何字体文件。

### 2. 加了第三档栏宽

参考页只有 692px（正文）和 800px（图表）。这个平台的表列多（公司/产品数/规则/AI/未匹配/
状态/时间 七列），硬塞进 800 会挤，所以加了 1120px 的数据栏。

**三档共用同一个左缘** —— 第一版我让三档各自居中，结果每段的左边缘都不在一条线上，页面是散的。
现在是一个外框定死左缘，正文靠内部 `max-width` 收窄。

### 3. 强调色的取舍

电光蓝 `#2251ff` 只用在四个地方：kicker、章节号、当前选中项、周期标签。
界面的操作色（按钮）仍是墨黑 —— 没让蓝色泛滥成第二个"主色"。

如果你觉得蓝色太跳，改 `:root` 里 `--blue` 一个值就能全站换掉。

## 如果决定真改，要动什么

样图只覆盖了**统计页**。真要落地，规模是这样的：

| 文件 | 改动 | 风险 |
|---|---|---|
| `css/style.css` | 重写 token 层 + 组件层，约 800 行 | **高** —— 全站 8 个页面共用 |
| `stats.html` / `stats.js` | 结构调整（卡片→分区），渲染函数基本不动 | 中 |
| `index/config/todo/taxonomy/...` | 7 个页面跟着换 | 中 |
| `htmlreport.py` | 导出的 HTML 报告是另一套内联样式，要同步改才不割裂 | 中 |

建议的做法（如果要做）：

1. **先只改 `stats.html` 一个页面**，其余页面维持原样 —— 两套风格并存一阵子不好看，但可回滚
2. token 层加一个开关变量，老 token 保留不删，出问题一行切回去
3. `htmlreport.py` 最后改 —— 它影响的是发给别人的文件，不是内部页面
