# 自动化数据处理平台

> ⚠ 本文档偏概览，细节以 `../CLAUDE.md` 为准（那里记录了各步骤的真实口径、增量机制与踩过的坑）。
> 2026-07 已取消 `_产品人工映射` / `_新增分类` / `_分类合并` 三个目录：人工匹配与 AI 复核的结果
> 一律回写映射输出，不再产生独立目录。文中若仍有相关描述，以 CLAUDE.md 为准。

公司产品数据 **映射 → 分类+清洗 → 复查 → id映射** 一站式 Web 平台。
后端 Python (FastAPI)，前端原生 HTML/CSS/JS（浅色主题）。
铁律：**原始数据零改动、全程可回退、每步后立即校验、按公司增量绝不重复处理**。

## 启动

```bash
cd /mnt/d/自动化数据处理/数据处理平台
python3 run.py
# 浏览器打开  http://127.0.0.1:8688
```

依赖（首次安装）：
```bash
python3 -m pip install --break-system-packages fastapi "uvicorn[standard]" python-multipart \
    pypdf img2pdf Pillow pikepdf cairosvg requests
```

## 页面总览

**② 数据处理页（映射 → 分类+清洗 → 复查）**：扫描公司（映射记忆标状态）→ 勾选步骤（可整体可单步）→ 运行；
未匹配自动进 _未匹配、AI 研判进复核队列；路径与首页一键流程共用配置。
**分类+清洗按公司增量**：页面上直接显示"本次将处理 N 家、其余跳过"，已完成的公司原样保留、绝不重复复制。

**🤖 AI研判复核页**：逐条或**批量**复核 AI 研判归类（勾选确认 / ⚡一键确认全部待复核，批量归档关键词=产品名；可点页面URL核实）。确认 → 研判逻辑以关键词归档进分类逻辑库（标签 `人工已确认_ai研判`，默认产品名、可改成更通用词），下次映射直接规则命中（学习闭环）；修改 → 产品在映射输出内移动到人工指定的分类（不跨树搬运），研判记录标记 已确认/已修改 全程留痕。

**📚 分类详情页**：12 一级 + 160 二级标准分类及全部定义（含新增分类标记），支持搜索、只看新增，可直接新增分类+定义（独立注册表，不写入标准体系）。

**🔑 分类逻辑页**：按 类别1/类别2/标签 浏览全部匹配关键词（原始库只读 + 自定义库可禁用/删除），可手动添加关键词（下次映射立即生效）；标签筛选可单独查看 AI 归档规则。

**人工介入的结果直接回写映射输出**：人工匹配与 AI 复核修改的产品都写进 `公司产品数据_产品映射`，
与规则命中、AI 研判的产品汇合成同一棵树，下游"分类+清洗"按公司增量自然覆盖 —— 不再有独立的人工映射目录和分类合并链。

**首页 · 🚀 一键全流程**：②映射→③分类+清洗→④复查 顺序执行，逐步校验、不通过不进入下一步；路径按统一前缀套预填（可改可存，`data/pipeline.json`）；支持公司级多线程（1-5，默认1）与 AI 研判模型选择。

**🖐 人工匹配页**：规则+AI 都未命中的产品自动进入 `公司产品数据_未匹配`（原目录结构、零改动）。选公司 → 按 公司名/产品名/页面URL 列出（URL 可点开产品页核实）→ 级联选 分类级别1/2（**悬停显示分类定义**，专业定义见 `config/category_definitions.json`）→ 重匹配直接回写**映射输出**；无合适分类时【新增分类】（支持 已有一级下新增二级 / 全新一级+二级，**强制填写定义**）；新分类注册于 `data/custom_categories.json`，后续下拉带【新增】标记，绝不写回标准分类树。重匹配成功后从 _未匹配 移除（原始数据另有保留），记录写入 过程记录/<公司>/人工映射记录.json。

**🕘 历史记录页**：记录每次任务（时间/步骤/公司/统计/路径/结果），可单条、批量、全部删除；删除只删记录，不动已输出数据。

**📤 统计结果导出（Excel）**：统计分析页可勾选公司或一键全选，导出 6 个工作表
（总览 / 公司明细 / 一级分类分布含柱状图 / 二级分类分布 / 公司×一级分类交叉表 / AI分析）。
选了任务模型会附一份面向管理层的 AI 分析（结论先行、只用统计数据、分类体系总数由代码喂入防止编造）。

**额外统计来源**：`pipeline.json` 的 `extra_sources`（默认 `D:\公司数据备份\待分类\{json,pdf}`）
只参与统计、不进入任何处理流程。产品判据放宽为"叶子目录含任意实质文件"（那批数据大多只有 PDF 没有 json），
英文 slug 公司名经 `公司id.json` 的 `name` 字段还原成中文名后合并计数。

**📊 统计分析页**：按周期（本周默认/近30天/全部）统计映射情况——类别分布、公司产品数量与映射构成（规则/AI/未匹配堆叠图）、未匹配高发公司排行、人工重匹配分类分布、新增分类清单；一键调用任务模型做 AI 整体分析（内置光电数据治理分析师提示词）。数据来源：映射记忆 `data/mapped_companies.json` + 历史记录 + 新增分类注册表。

**增量处理（两套记忆）**：映射记忆 `data/mapped_companies.json` 管 ②，清洗记忆 `data/cleaned_companies.json` 管 ③（指纹=映射输出下该公司的产品数+子树最大mtime）。

**映射记忆细则**：每家公司映射成功后记入 `data/mapped_companies.json`；再次扫描时自动标记 新增 / 已完成 / 有更新（产品数变化），映射页默认只勾选新增和有更新的公司，一键全流程默认跳过已完成公司（可勾选"全部重做"）。

## 功能页明细

| 页面 | 功能 | 要点 |
|---|---|---|
| ① 配置 | 搭建 LLM 任务模型（最多 5 个） | 预置 DeepSeek/千问/GLM/Kimi/豆包/OpenAI/Claude/Gemini + 自定义 OpenAI 兼容；角色 + Prompt + Skill 挂载；测试连通。Key 仅存本机 `data/task_models.json` |
| ② 产品数据映射 | 按 product-folder-standardizer 规则映射进 12 大类/160 子类 | Part-2 硬规则 → 产品名 → 父级退回 → **AI研判** → 未匹配；复制不移动；公司级多线程(1-5)；映射输出只含命中产品，未匹配自动进 `_未匹配`；`映射报告.md`/`研判归类.json` 存 `_产品映射_过程记录/<公司名>/` |
| ③ 分类+清洗（合一） | 判类别 → 复制 → 就地清洗 | **分类判的是"参数载在哪"**：有原始 PDF（参数在说明书）或有参数图（参数在图片）→ 类别3_有pdf或参数图；都没有则按 json 参数 非空/空 分 类别1_json_非空 / 类别2_json_空。产品展示图不参与判定。主图→其他图→参数图 转PDF后前置并入说明书PDF；json/PDF 重命名为 `父文件夹名.json/.pdf`。**按公司增量**，输出固定目录 `公司产品数据_清洗后/<类别X>/<公司>/…`，重做一家公司只清掉这一家 |
| ④ 数据复查 | 审计三项，均须=0 | **核心：PDF 是否被误删**（合并后改名为「产品名.pdf」，原 PDF 恰好同名时删原件会连合并产物一起删掉）；另核对产品数量与页数完整性做交叉印证。基准取**映射输出**，可全量或只查一家公司 |
| ⑤ id 映射 | 公司名→公司id、一级/二级→分类id | 输出 `<类别X>/<公司id>/<分类id>/<产品名>/<产品名>.json\|.pdf`（两层分类压成一层）。二级分类无 id 时退回用一级 id；查不到 id 的公司/分类按原中文名输出、零丢失并单列。按公司增量 |

## 推荐流水线

```
原始爬取数据
  ②映射(选AI任务模型) → 公司产品数据_产品映射/公司/cat1/cat2/产品 (+_未匹配, 映射报告.md)
       ↑ 人工匹配 / AI复核修改 的结果也回写到这里
  ③分类+清洗(输入=映射输出) → 公司产品数据_清洗后/类别1|2|3/公司/…/每产品 = 父名.json + 父名.pdf
       按公司增量：只处理新增或有变化的公司
  ④复查(清洗后 vs 映射输出) → 三项均为 0 才进入交付
  ⑤id映射 → 公司产品数据_最终数据/类别X/公司id/分类id/产品名/产品名.json|.pdf
```

## id 表

两张表同构，都放 `公司产品数据_id表/`，格式 `[{"id": "…", "cnName": "…"}]`：
- `公司id.json` —— 公司中文名 → 公司 id
- `产品id.json` —— 分类中文名 → 分类 id（一级二级同表，靠名字查；已确认 12 一级与 160 二级无重名）

平台会生成 `产品id.模板.json`（含全部 172 个分类名、id 留空）供填写。缺表时 id 映射步骤自动禁用并提示。

查名顺序：**别名表 → 原名精确 → 去掉目录名尾部消歧后缀（`_` / `_1`）重查**；中文名与英文名都建索引。
仍查不到的按原中文名输出、零丢失并单列。别名表 `data/id_aliases.json` 由平台维护，
可在数据处理页「单独执行 id 映射」的表格里直接给某个目录名指定 id，不改动你维护的外部 id 表。

**单独执行 id 映射**：数据处理页第 4 张卡片。公司列表来自**清洗后目录**（与上方「识别到的公司」
那张来自输入目录的表是两个不同集合），可勾选公司、只选未映射的、就地补 id，独立执行。

## 路径与运行环境

- 路径输入 **Windows / WSL 双兼容**：`D:\自动化数据处理`、`D:/x`、`/mnt/d/x`、带引号的"复制路径"、甚至 `/mnt/D:\x` 混写都会自动归一化；在 Windows 原生 Python 运行时反向转换为盘符路径。
- 所有处理任务都带**实时反馈面板**：进度条 + 动态计数器（已合并PDF/AI研判/损失…）+ 当前正在处理的条目 + 滚动日志，可随时取消。
- **原始数据保护（强制）**：映射/分类=复制落地；清洗=必须指定输出目录，先复制再清洗副本；ID替换=以 id 名复制到输出目录。任何步骤都不修改输入目录，错误可随时从上游副本回退重做。

## 已内置的防坑措施（继承 product-data-pipeline 实战经验）

- **大小写守卫**：/mnt/d NTFS 大小写不敏感，原 PDF 名与父文件夹同名（含仅大小写差异）时不会误删合并产物；损坏同名原件先改名 `_损坏原件.pdf` 保留。
- **SVG 伪装 .jpg** → cairosvg 转 PDF 合入，不丢弃；无效/损坏图片跳过不中断；全部无效不生成 0 页 PDF。
- **损坏 PDF** → strict=False / pikepdf 修复后合并；修不好则保留原件、图片单独成 PDF。
- **审计三重点**：①产品数量核对（原始 vs 清洗后逐产品对应，缺失单列）②合并 PDF 是否被误删（原有图片/PDF、清洗后无任何 PDF 的产品单独成清单重点排查）③页数完整性；匹配键相对路径优先，回退 公司+产品名，**绝不用页面URL**。
- **ID替换支持嵌套结构**：目标目录可直接指向清洗后根目录，自动穿透 类别X 等结构层找到公司层，输出保留原层级。
- **AI 研判约束**：只作最后兜底，不覆盖规则命中；结果必须是分类树内已存在的 category（置信度 0.90、报告单列、可复核）；无合适子类则保留未分类并据实说明。
- **重跑安全（增量语义）**：③ 只清空并重建『本次要处理的那几家公司』的子树，其他公司原样不动；② 覆盖同名叶子前先删旧副本；ID 替换幂等（已是 id 的公司照常复制、不重复解析）。
- **人工成果不丢**：人工匹配/AI复核定过的产品写入 `人工映射记录.json`，映射重跑时直接沿用，不会再次落进 `_未匹配` 要求重做；同时关键词归档进自定义库，同类新产品自动命中。

## 目录结构

```
数据处理平台/
├── run.py               # 启动入口
├── backend/             # FastAPI 后端
│   ├── main.py          # 路由
│   ├── store.py         # 任务模型存储 + 供应商预置
│   ├── llm.py           # LLM 调用（OpenAI兼容/Anthropic；本地地址自动绕过代理）
│   ├── jobs.py          # 后台任务/进度/日志
│   ├── mapping.py       # ② 映射引擎（含 AI 研判、人工结果粘性）
│   ├── consolidate.py   # ③ 分类+清洗合一，按公司增量
│   ├── classify3.py     # └ 分类判定规则（被 consolidate 复用）
│   ├── clean.py         # └ 单产品清洗逻辑（被 consolidate 复用）
│   ├── registry.py      # 映射记忆 + 清洗记忆（增量判定）
│   ├── audit.py         # ④ 审计（PDF误删/产品数/页数）
│   └── idmap.py         # ⑤ 公司id + 分类id 映射
├── config/              # 双语 mapping_*.json + company_categories.json（12大类/160子类）
├── skills/              # skill 库（product_category 等，可在配置页上传扩充）
├── data/                # 平台数据（task_models.json 等）
└── frontend/            # 6 个页面 + css/js
```
